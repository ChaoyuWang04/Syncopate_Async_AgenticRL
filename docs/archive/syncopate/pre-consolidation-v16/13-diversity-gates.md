## 0 · 为什么需要一套独立的门禁

2026-08-17 量了一次才发现：**1670 条 case 只有 63 种句式**，7 个模板 90–150 条题
共用同一句话（只有 ID 和数字不同），最高频那句占全库 **17.6%**。

后果**不是"数据少"**，是模型可以**靠表层特征路由** ——
看到「能不能铺到 US、GB、JP」就走那条 9 步链，根本不用理解任务。
上线后用户话术千变万化、多个诉求夹在一起，这套就塌了。

⚠️⚠️ **而冻结 EVAL 用的是同一批句式，所以它测不出这件事。**
评测分数会很好看，而模型学的是一个上线就失效的技能。
⇒ **多样性必须有独立门禁，不能靠"看评测分数好不好"。**

---

## 1 · 十一条门禁

| # | 判据 | 防的是哪种失效 |
|---|---|---|
| **D1** | 每格 **≥5 种句式** | 一个模板一句话 |
| **D2** | 同格平均相似 **≤0.35** 且最大 **≤0.75** | 5 句其实是同义词替换 |
| **D3** | 最高频句式占比 **≤5%** | 某模板条数多，把全局带偏 |
| **D4** | 每格 **≥4 种表达结构** | 只换词，不换说话的方式 |
| **D5** ★ | **句式不能预测档位**（见 §2） | 看到那句话就知道答案 |
| **D6** | 每个实体轴 ≥5 种取值、最高频 ≤40% | 模型记住那几个 ID 就能过关 |
| **D7** | ≥5 种工具菜单组合 | 菜单恒定 ⇒「按意图剪枝」这条轴是死的 |
| **D8** | gold 工具序列 ≥5 种、最高频 ≤35% | 所有题一条链，背下来就行 |
| **D9** | 五种 behavior 都要有样本 | 某种行为样本太少，学不会 |
| **D10** | 每模板 ≥2 种结局 | 结局恒定 ⇒ 不用看世界就能答对 |
| **D11** | 题面长度变异系数 **≥0.25** | **长度本身**成为路由信号 |

★ **格子 = 模板 × entry_mode。** 两种入口的题面本来就不同，混在一起算会**虚高**多样性。

## 2 · ★★★ D5 是唯一一条真的抓到过 bug 的

题面改写上线的第一版按 `stable_hash(index)` 选句式，而**档位也是 index 推出来的**
⇒ 两者相关。实测：**`empty` 档独有 2 条句式、`superseded` 独有 2 条**。

> 意味着模型看到那句话，**就知道这题会查空** —— 根本不用等检索结果。

既有的 `test_prompt_is_identical_across_arms` 当场把它判红了 —— 那条测试守的正是这个。

**修法不是放宽判据，是改实现**：`_phrase(..., stratum=...)` 按 **(档 × entry_mode)
轮转**选句式 ⇒ **构造保证**各档句式集合完全相同，而不是事后统计说"看起来挺均匀"。

### 2.1 判据分两档，理由是数学上的不是妥协

```
D5a 严格（集合必须完全相同）—— 真·分档轴
    rag_state / insight_state / safety_line_state / data_maturity / season_phase
    「同一句话、不同世界、不同正确动作」，3 档、每格样本远多于句式数
    ⇒ 轮转能做到完全均匀，做不到就是 bug

D5b 宽松（不许有句式被单一档独占）—— 其它轴，尤其 outcome
    FAIL 有 **10 种结局**而句式只有 7 种，每格约 7.5 条
    ⇒ **集合相等在数学上不可能**（鸽笼原理）
    但真正要挡的利用方式是「看到这句话就知道是哪一档」，
    写成「没有任何句式被某一档独占」就够，而且做得到
```

⚠️ 第一版对所有轴一刀切用 D5a，把 FAIL/INJ 判成不达标 ——
**那是判据不可能被满足，不是数据有问题。** 记在这里免得下次又改回去。

## 3 · 指标本身也会骗人 —— 三次修的是指标不是数据

**① 归一化没做干净 ⇒ 多样性虚高。**
第一版靠正则抹实体，`halloween_hook_e_v1` 这种没抓到，CRE 报 **43 种句式**，
而最相似的一对其实是 **0.91**（同一句话换了素材名）。
⇒ 改成**用 case 自己的 `entities` / `context` 去抹**，比猜正则准。

**② 词表手抄漏了两个。** 特征词是闭集，第一版手抄漏了「暗色调」「前后对比开场」，
ATTR 的相似度虚低成 0.88 判不达标 —— **问题在指标不在数据**。
⇒ 改成从 `_FEATURE_CN` 直接 import。

**③ 统计量选错了。** 「最大两两相似」会**结构性地惩罚短请求**：
8 个词改 2 个词，Jaccard 就是 0.75。于是把
「帮我把日预算提到 400」和「日预算能提到 400 吗」判成不达标 ——
**而那确实是两种说法。**
⇒ 改成**平均管铺开、最大只挡近乎重复**。
★ 但阈值不是往后退着凑数据：同一轮把真正过近的三对改写掉了，
改完全局平均相似中位 **0.22**、最差 0.33，离 0.35 仍有余量。

> **教训：判据本身要被怀疑一遍。** 一条指标"跑出来是红的"有两种可能 ——
> 数据不行，或者指标不行。先分清是哪一种，再决定改哪边。

## 5 · 怎么加新指标

`syncopate/pipeline/data_gates.py` 里每个 `check_*` 返回 `(通过与否, 打印行)`，在 `CHECKS` 注册。

⚠️ **新指标必须能回答两个问题，否则不要加**：

1. 它防的是**哪一种具体失效**？（要能举出失效长什么样，最好是真出过的）
2. 阈值**怎么定的**？实测反填 / 从设计文档来 / 还是拍的 —— **拍的要写明是拍的**。

★ 还没有覆盖、但值得以后加的：
- **工具返回的多样性**（observation 的文本模式）—— 现在没量过
- **history 长度分布**（多轮时才有意义）
- **真实用户话术的对照**：M10 影子模式攒够真实 query 之后，
  用它当**校准基准**量我们合成分布偏了多少 —— 那才是这套指标真正的锚

## 6 · 别再重新讨论的（D 族）

- **格子按 (模板 × entry_mode) 分**，不按模板分（混算会虚高）。
- **D2 用平均管铺开、最大只挡重复**，不要改回"只看最大值"。
- **D5 分 a/b 两档**，不要一刀切。
- **归一化用 case 自己的 entities/context**，不要退回猜正则。

# L 部分 · 三桶泄露门禁（原 15 号，2026-08-17 建，2026-08-19 并入）

## L0 · 事情是怎么被发现的

切分报告一直写着「三桶零重叠 ✅」—— 它用 SHA-256 算「完整渲染的 prompt + gold +
behavior」的指纹，实测确实 0 重叠。**但换个角度查就露了**：

```
ATTR_0001 [EVAL]  「我们在 GB 想扩量。真人出镜这个素材特点到底有没有用？」
ATTR_0048 [SFT ]   题面一字不差，gold 答案也一字不差（lift 0.1791）
```

两条的 `campaign_id` 不同 ⇒ 完整 prompt 不同 ⇒ 哈希不同 ⇒ 检查通过。
而模型要答的那件事完全一样 —— **把 SFT 那条背下来，不读世界也能答对 EVAL 这条。**
v13 实测：**62 / 278 = 22.3% 的 EVAL 有这样的孪生**。
⇒ 与 D5 同一条教训：**一个判据只覆盖它作者当时想到的那种形状。**

## L1 · 两级判据

| | 键 | 适用范围 | 性质 |
|---|---|---|---|
| **L1** | (题面**原文**, gold 答案) | 所有模板 | 硬门禁 |
| **L2** | (题面**句式**, gold 答案) | 除豁免模板外 | 硬门禁 |

「句式」= 用 case 自己的 `entities`/`context` 抹掉实体数值后的题面（不猜正则）。

**L2 的模板豁免必须显式列出并写明理由**（CHAT/CLAR/REJ —— 这三类「答案由问法决定」
是要训的能力不是漏洞；不豁免会把受影响面从 22% 虚涨到 48%）。
⚠️ 豁免不许"因为它红了就加进来"。

**两类结果性质不同，不能混成一个 passed**：

```
涉及 EVAL 的泄露    = 有效性问题（评测数不可信）⇒ 硬门禁，必须 0
SFT ∩ RL 的重复     = 效率问题（组内方差 0 ⇒ 零梯度）⇒ 报出来，不阻塞
```

v13 修完：EVAL 受影响 **0**；训练池内仍有 L1 40 组 / L2 77 组（零梯度率的已知来源之一）。

## L2 · 修法是构造保证，不是事后查

**按「泄露组」分层取样，组是原子的**：同一泄露键的所有 case 整组进或整组不进 EVAL。
⚠️ 试过「先选完再把孪生拉进来」—— EVAL 从 278 膨胀到 507，SFT/RL 被抽干。

```
v13 修复前   EVAL 278 / SFT 511 / RL 881   受影响 EVAL 62 (22.3%)
v13 修复后   EVAL 343 / SFT 503 / RL 824   受影响 EVAL  0
```

**为什么非查不可**：这份冻结 EVAL 是所有配对比较的基线，配对 MDE 只有 0.013，
两成噪声足以淹掉真实效应。⇒ 「三桶零重叠」以后要连口径一起说
（`content_hash` 口径和 L1/L2 口径**都过**才算零重叠）。

## L3 · 别再重新讨论的（L 族）

- **L2 必须分模板豁免**，且豁免写理由。
- **EVAL 泄露是硬门禁，训练池重复只是警告** —— 别把后者拿来卡门。
- **修法是按组取样**，不是"选完再拉孪生"。
- `content_hash` 那条检查**保留**，它挡的是另一种形状（完全相同的 case）。
