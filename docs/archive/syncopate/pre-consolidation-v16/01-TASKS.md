**唯一入口**：[scripts/v16_pipeline.sh](../../scripts/v16_pipeline.sh)，profile 使用 smoke。实际 Modal 操作方式见 [31](31-modal-and-new-stack.md) 与 [modal_app/README.md](../../modal_app/README.md)。

T1-0 是代码核对后确认的当前缺口，不是预防性猜测：

- sft-train 的 smoke 档写入带 smoke 后缀的目录，sft-eval、sft-select 和 merge 仍读取正式目录。
- rl-train 的 smoke 档默认从学生底座开始，没有读取本轮合并后的 SFT 模型。
- opd-train 的 smoke 档会清空上游 adapter，并强制回到学生底座。
- 现有管线测试检查了“阶段和脚本存在”，但没有检查“后一阶段真的读取前一阶段的 smoke 产物”。

### T1 总完成条件

只有同时满足下面四条，T1 才能从队列移除：

1. T1-0 到 T1-6 全部完成，中间没有靠裸底座、错误目录或跳过真实工作换来的“绿”。
2. 每一阶段的产物都被下一阶段实际读取，而不只是文件存在。
3. 失败与重跑有可复查的审计证据；最终一次全链没有未解释红项。
4. 结论明确写成“真实数据全链 smoke 通过”，不写成“候选模型已验收”或“可以上线”。
