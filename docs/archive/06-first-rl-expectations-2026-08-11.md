## 1.4 兑现：M7（2026-08-14，fully_async / 150 步 / 起点 v11-e1）

**四段式记账，推翻的预测不删。**（⚠️ 该跑跑在两个基石 bug 之上，数字见 21 号清单 ⛔(21)）

### P1「涨的主要是 CRE/MISS/BUD」—— 部分推翻

- 实测：BUD +0.055 ✅、FAIL +0.046、RAG +0.030；但 CRE −0.026 ❌、FRESH −0.062、MISS 仅 +0.006。
- 推翻后：「低分 + 有梯度」不足以预测涨幅；FRESH 掉得最多而基线并不低（0.882）——
  RL 会动到本来做得好的题。**教训：预测涨幅按「组内方差」分组，不按「均分高低」。**

### P9「分布漂移恒等于 0」—— 成立，但理由和写的时候想的不一样

- 实测：async 下也是 0.000，下发 7200 = 训练 7200。
- 推翻后：真因是 `partial_ratio = 0` —— 轨迹太短（~700 token）相对同步周期（4 步 ≈300s），  ⛔(21)
  没有任何轨迹跨越版本边界；且 `--partial-rollout True` 是续跑不是丢弃。
  ⇒ 不是"没测到漂移"，是**这一跑里没有漂移可测**。
- 教训：① 要让这条线有内容，得让轨迹真的跨越版本边界（调大 latency-scale 或缩短同步周期）；
  ② `record_dispatch` 当时记在轨迹末尾 ⇒「下发」实为「跑完」（后由 B4 移到真下发点）。

### 停止条件全部通过，且判据都实跑验证过

ESS 0.74–0.88（键名 `rollout_corr/rollout_is_eff_sample_size`，不叫 ess）/  ⛔(21)
决策位熵 0.027→0.072（升了）/ grad_norm 0.011–0.06 / 长度 508–738 无增长 /
cap 随 reward 同向下降。⚠️ cap-vs-reward 控制台看不到，要聚合 `rollout_dumps/*.jsonl`。

## 附录 A · v8 基线的预期（写于 2026-08-11，跑之前）

沙盒大改后旧 base 数据（0.502 / EVAL 64 条）作废：单位改分、写动作要幂等键、22→24 工具、
渲染顺序变、十类失败注入，EVAL 64→104。

预测：P1 总体 0.25–0.40 · P2 F 类 <0.20 · P3 写动作大面积失败（不知道要传 `client_request_id`）·
P4 单位错（840 元填 840 不填 84000）· P5 全灭格子集中在 FAIL_* · P6 注入类非零命中。

★ P3 是「廉价死格」（约定未知不是能力缺失），SFT 一个 epoch 就能解决；
读结果必须剥掉这一层，否则会把「不知道字段」误读成「不会任务」，把 SFT 桶选错
（`p=0` 有两种成因，混在一起会把 SFT 引向错误方向）。

**不测旧 SFT 的理由**：`v3_ctrl` 是在另一个世界训的，拿它测 v8 分数低是世界变了，
数字没有意义。正确顺序:测 base → 重切 SFT 桶 → 在 v8 上重训 → 再评。
