# E24 · bf16 合并损失**在任务分上值多少** —— 实测 −0.025（MDE 0.016）

> 建于 **2026-08-18**（9 小时队列 T1）。起因：主线 2026-08-18 交接 §11.5-① 与复盘 §1-⑥（两份均已删/归档）
> 指出**配对比较的两端不是同一个起点模型**，要求跑一次"RL 真起点"的审计。
> 关联：[`E22 §6.1`](E22-lora-never-synced.md)（同一个 bf16 现象在 **RL** 那一级的样子）

---

## 0 · 一句话

**RL 的真实起点（合并后的 SFT 模型）比此前一直当基线用的那个模型（裸基座 + SFT adapter）
在冻结 EVAL 上低 0.025 —— 而最小可检出差异只有 0.016。
⇒ 此前所有 SFT↔RL 的配对比较，基线那一端都比 RL 的真实起点强了 0.025。**

---

## 1 · 问题：两端不是同一个模型

```
「RL 之前」的分数   跑在  裸基座 Qwen3-4B + SFT 的 adapter      ← A（_audit/v13_sft_e1.json）
RL 的实际起点       是    models/Qwen3-4B-sft-v13-e1（**合并后**）  ← B
「RL 之后」的分数   跑在  B + RL 的 adapter
```

⇒ 配对比较的前提是「同一个起点模型」，而 **A ≠ B**。差多少此前只在**权重空间**量过
（主线 18 §3.3：SFT 增量占基座 0.42%，合并进 bf16 后**保真残差 0.36**，判为"可用"）。
**本实验把它换算到任务空间。**

---

## 2 · 实测

尺子：冻结 EVAL 343 条，4 卡分片并行，`scripts/infra/eval_parallel.sh`（口径与所有历史审计一致）。

```bash
MODEL=models/Qwen3-4B-sft-v13-e1 bash scripts/infra/eval_parallel.sh "" _audit/v13_sft_e1_merged.json
#                                                              ↑ 空串 = 只评这个模型本身
```

| | 基线 A（裸基座 + SFT adapter） | 候选 B（合并后 = RL 真起点） |
|---|---|---|
| **reward 均值** | **0.756** | **0.731** |
| 配对差值 | — | **−0.025**（标准差 0.151，标准误 0.008） |
| 最小可检出差异 (MDE) | — | **0.016** |
| 结论 | — | **退化 0.025，t = −3.1** ⇒ **显著** |
| 逐题三计数 | — | 显著变好 **27** / 没动 **263** / **显著变差 53** |

**变差集中在** `CONF×12 · FAIL×8 · POL×6 · BUD×4 · INJ×4 · POLM×4`
**变好几乎全是 FRESH**（`FRESH_0001 +0.58`、`FRESH_0000/0117/0145 +0.50`）

★ 一处**反直觉但重要**的观察（零梯度构成）：

```
                        有梯度   全灭   饱和   卡死
A 裸基座 + SFT adapter    222     3     96     22
B 合并后（RL 起点）       246     3     77     17
```
⇒ **合并后的模型 reward 更低，但"有梯度"的题反而更多、饱和更少。**
⇒ 对 RL 训练而言这不全是坏事（学习信号更多），**但它确实是一个更差的起点**。

## 3 · 后果

### 3.1 ★ 旧的配对比较**系统性低估了 RL 的效果**

```
旧口径   RL 后的分数  −  「裸基座 + SFT adapter」的分数
正确口径 RL 后的分数  −  **「合并后的 SFT 模型」的分数**
而后者比前者低 0.025  ⇒ **旧口径把 RL 的效果压低了约 0.025**
```

⚠️ **不要拿这个去"修正"M7-b 的数字** —— M7-b 同时被 [`E21`](E21-ddp-not-syncing.md)（只学 1/3 数据）
和 [`E22`](E22-lora-never-synced.md)（rollout 策略恒为 π₀）作废，**再修正一个作废的数没有意义**。
⇒ 这个 −0.025 的用途是：**从今往后所有 SFT↔RL 的配对比较，基线一律用
`_audit/v13_sft_e1_merged.json`**（本实验的产物）。

### 3.2 与权重空间的测量互相印证

```
权重空间（主线 18 §3.3）  SFT 增量占基座 0.42% ⇒ 合并进 bf16 后保真残差 0.36
任务空间（本实验）        同一次合并 ⇒ 冻结 EVAL 上 **−0.025，是 MDE 的 1.6 倍**
```
⇒ **"保真残差 0.36 判为可用"这句话现在有价了：可用，但要付 0.025 的任务分。**
⇒ 而 RL 那一级增量的保真残差是 **0.87**（E22 §6.1）——
**同一条曲线上更远的一点，这也是为什么 `--lora-merge` 那条路必须被否掉。**

### 3.3 ⬜ 它把一个待设计的问题变得更尖锐

主线 18 §3.4 记着一条未解决的：**「下一轮 RL 怎么接着上一轮」** ——
合并这条路被 bf16 堵死，而 verl 用 LoRA 时 reference = 关掉 adapter = 基座。
⇒ 本实验说明：**"合并"这一步本身就在持续付费（每合并一次 −0.025）**。
⇒ **值得重新考虑：RL 是不是应该直接从「裸基座 + SFT adapter」起步，而不是从合并模型起步。**
⚠️ 但那要先解决 reference 指向谁的问题 —— **这是设计题，不是 bug**，需要 Chaoyu 定。

## 5 · 顺带修的一个 bug

`scripts/infra/eval_parallel.sh` 的 `ADAPTER="${1:?}"` 把**空字符串**也当成"没给"
⇒ 主线文档里评基座的那条命令 `eval_parallel.sh "" out.json` **一直跑不通**。
已改成 `${1?}`：参数必须存在（保住"别忘了想清楚 adapter"的用意），但**允许显式为空**。
