## 3 · 🆕 五件你们需要知道的新事

### 3.1 🔴🔴 **RL 在教模型"不拒绝"** —— 这是给你们的活（reward 设计）

```
            该 defer   误 defer   任务分
RL 起点        97%       4.1%       —
lr 3e-5        83% 🟠    1.3%     +0.101
lr 1e-4      **0%** 🔴🔴 0.0%     +0.063  ← **一次都不拒绝了，而总分还是正的**
```
⇒ 与 `fabricated_safety_line_cap +3`、`REJ −0.188` 连成一条一致的图景：
**当前 reward 下 RL 会系统性学会"不拒绝"，lr 越大越彻底。**
⇒ **这是 reward 设计问题，不是 infra 问题。** 已排为 infra 队列第 1 项但**归你们**。见 [`E20 §7.9`](E20-rl-not-learning.md)

### 3.2 ★ **总分连着两次盖住真实差异** —— 建议加三条常驻判据

```
第一次  总分 +0.101 很漂亮，而 defer 从 97% 掉到 83% —— **逐题三计数**才让它显形
第二次  两种方法总分**完全打平**（+0.000），而 defer 差 **14 个点**
        —— **连三计数都没让它显形**（41 好 / 269 没动 / 33 差，看起来就是噪声）
```
⇒ **三计数比均值好，但它仍然是"打包"判据。**
⇒ **建议 `compare` 每次都打这三个**：`defer` 双向率 · `REJ` 类分数 · `fabricated_safety_line_cap`。
它们各自是"某一类行为"的直接读数，不会被总分吸收掉。

### 3.3 ⚠️ **训练分和任务分给出了相反的排序**

```
训练分（critic/score/mean）  lr 1e-4 **+0.123** > lr 3e-5 +0.109   ⇒ 看起来更好
任务分（冻结 EVAL 配对）      lr 1e-4 **+0.063** < lr 3e-5 +0.101
                             直接配对 **−0.039（t=−3.1，显著退化）**
```
⇒ **训练时看到的分数不能用来选配置。** 这条对你们挑 ckpt / 调参同样成立。

### 3.4 ⚠️ 你们 §4 那条口径更正有一个**隐藏前提**

```
「rollout_dumps 文件数 = 优化器更新次数」在 m7b 上成立，
**是因为那时 ppo_mini_batch_size == train_batch_size（都是 6）** ⇒ 每 fit step 恰好 1 次更新
⛔ 一旦 mini_batch ≠ train_batch，这个等式立刻不成立
```
⇒ 我们装了真正的计数器（`SYNCOPATE_OPT_STEP_PROBE=1`，直接数 `optimizer_step` 调用次数）。
⇒ 顺带：**`--steps` 在 `mini_batch` 变化时换了含义** —— 它固定的是"更新多少次"，不是"训练多久"。
见 [`E20 §7.10`](E20-rl-not-learning.md)
