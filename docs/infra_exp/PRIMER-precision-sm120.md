> [`E19`](E19-fp8-in-training.md) FP8 训练侧+serving 侧）。语言刻意从简。

## 1 · 精度格式都是什么

| 格式 | 位分配 | 一句话 |
|---|---|---|
| bf16 | 1符号+8指数+7尾数 | 训练默认。量程和 fp32 一样宽，精度约 3 位十进制 |
| **FP8 E4M3** | 4指数+3尾数 | 前向主力：精度多、量程窄（±448） |
| FP8 E5M2 | 5指数+2尾数 | 传统上给梯度：量程宽、精度少。DeepSeek-V3 证明配好缩放可以不用它 |
| **FP4 E2M1** | 2指数+1尾数 | 只能表示 ±{0,0.5,1,1.5,2,3,4,6} 共 16 个值——**不配块缩放没法用** |

**为什么低精度必须配"缩放因子"**：格式本身量程太窄，要先把一块数除以一个因子压进量程，
算完再乘回来。缩放的粒度就是精度/开销的核心权衡：

```
per-tensor   一张量一个因子      最粗，离群值毁全局（我们 E19 §7 探针用的这档）
细粒度块     DeepSeek 1×128/128×128  精度好，但 Hopper 硬件不认识 ⇒ 软件硬扛（DeepGEMM）
MX 标准      32 元素共享 1 个 e8m0（纯 2 的幂）   ⇒ MXFP8/MXFP4
NVFP4        16 元素共享 1 个 e4m3（带尾数，更准）+ 全张量 fp32 二级缩放
```

**Blackwell 的代际变化**：MX/NVFP4 的块缩放**被做进 tensor core 的 MMA 指令**
（元素+缩放两路输入，管线内应用）——Hopper 时代"细粒度精度 vs 硬件速度二选一"取消了。

**为什么选 FP8 不选 INT8**：不是硬件独占（5090 两者都有），是数值形状——LLM 激活重尾，
INT8 均匀格点要靠离线校准救；FP8 浮点格点天然零附近密、远处疏，可在线动态量化。

## 2 · 计算单元：同一批 tensor core，不是各设一套

每个 SM 里的 tensor core 是**一条多精度数据通路**：同一片乘加阵列按指令切成不同宽度
lane ⇒ 窄格式每拍塞更多元素。但每种格式的电路是**显式设计**的（FP8 Ampere 没有、
FP4 Hopper 没有），不是"字节小自然快"。逐元素运算（softmax/norm/量化 amax）走 CUDA core，
与 tensor core 并行但常常成为量化的"逆风"成本。

★ **本机实测的速率阶梯**（E16 §7，寄存器驻留峰值）：
`bf16 258 → FP8传统 516 → FP8块缩放 1026 → FP4 2055 TFLOPS = 1:2:4:8`
——其中 **"传统 FP8 mma 只有原生一半速率"是我们自己测出的关键事实**，
公开资料没有明说；FP8 满吞吐必须走 `kind::mxf8f6f4` 块缩放指令形式。

## 3 · 我们的卡 vs 数据中心卡

| | **RTX 5090 ×4（本机）** | H100 | H200 | B200 |
|---|---|---|---|---|
| 架构 | Blackwell 消费级 **sm_120** | Hopper sm_90 | 同左 | Blackwell DC sm_100 |
| 显存 / 带宽 | 32 GB / ~1.8 TB/s | 80 / 3.35 | 141 / 4.8 | 192 / ~8 |
| BF16 / FP8（dense 约） | 210 / 420 TFLOPS | 990 / 1980 | 同左 | 2200 / 4500 |
| FP4 | **✅ ~840+（H 系没有）** | ❌ | ❌ | ✅ ~9P |
| 互联 | PCIe Gen5，**无 NVLink/P2P** | NVLink 900GB/s | 同左 | NVLink5 1.8TB/s |

四条含义：① FP8/FP4 是 5090 性价比核心，**但软件栈滞后**（torch 派 Ampere 代 kernel）；
② FP4 是 5090 有而 H100/H200 没有的牌；③ 32GB+无 P2P 决定了训推分离/DDP/LoRA-only ckpt
一整串设计（02 §1）；④ sm_120 ≠ sm_100，数据中心 Blackwell 的 kernel 不通用。

## 4 · kernel 软件栈地图（从"拿来用"到"裸写"）

```
cuBLAS/cuDNN     成品店：闭源库，货架上没有的没辙
CUTLASS / CuTe   乐高厂：开源 C++ 模板拼自己的 GEMM；CuTe 是布局代数地基
Triton           说人话的乐高：Python 写瓦片逻辑，编译器包办访存
                 ⚠️ 对新硬件常年滞后——本机实锤 tl.dot_scaled 是 bf16 仿真（E16 §6）
TileLang         同层但旋钮显式（TVM 血统）；DeepSeek JD 点名；A3 正餐选它
inline PTX       裸金属：直接写 mma 指令——sm_120 块缩放路径目前唯一入口（E16 §7）
```

**Transformer Engine**：NVIDIA 的 FP8/FP4 训练**库**（te.Linear 等层替换 + 缩放自动管理），
不是框架；名字也被市场材料借来指"FP8 硬件+软件"整包。对消费卡支持残缺。

## 5 · 训推精度组合——什么安全什么危险

| 组合 | 风险 | 一句话 |
|---|---|---|
| bf16 训 + FP8/FP4 **serving** | 低 | 无反馈回路，配对评测闸把关即可（E19 §8 实测） |
| bf16 训 + FP8 **rollout**（RL 采样） | **高** | 失配进学习回路 = 偷偷变 off-policy；误差按序列长度累积（我们 0.03/token×654≈20 nats；文献 8K token 训崩）；TIS/IS 修正能缓解**关不上** |
| FP8 训 + FP8 rollout（端到端一致） | 中 | 2026 共识方向（Jet-RL/NVIDIA）：两侧同方式量化，误差在比值里对消 |
| NVFP4 | 分对象 | serving 大模型可（配校准/QAT）；**4B agentic 实测判死**（E19 §8） |

关键仪表含义：我们的常驻判据③（trainer↔vLLM logprob 差回 3.4e-4 地板）在任何**单侧**
量化下都会被打飞——上量化必须连着判据重标定一起设计。
