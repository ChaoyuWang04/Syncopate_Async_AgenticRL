# Infra · 背景调查、实验与记录协议

> 本协议适用于训练与推理 infra 的每个独立实验。任务见 [TASKS](01-TASKS.md)，组合选择见 [SYSTEM](02-SYSTEM.md)。项目以开源贡献为方向；实验组负责实验和 DRAFT 移交，正式 PR 调查与提交由 [upstream](../upstream/README.md) 负责人完成。

## 1. 新编号、存储与文档分工

新系列名为 `infra-probes`，从 **B00、B01、B02……** 独立编号。G0～G7 是主题分组，Q 是稳定待办 ID，P 是可调整优先级；一个 B 编号对应一个真实场景探索或由证据触发的独立优化问题，不预先给所有候选分配编号。

- 选定具体调查问题时，在 TASKS 登记 `infra-probes/B00` 和 REPORT 链接；先检查新目录及队列，避免并行认领重号。编号只增不复用，调查关闭也保留。
- 人读目录采用 `B编号-简短主题`，例如 `B06-GDN快速路径`；目录地图见 [experiments/README](experiments/README.md)。B编号、Volume路径与既有run-id保持稳定，主题后缀只帮助导航；改名必须修复现行链接，不改历史命令、源码SHA或原始证据地址。
- 新实验记录放 `docs/infra_exp/experiments/B00-主题/REPORT.md`；旧 `_audit/infra/B01/` 等原地封存。跨目录引用必须带系列名或完整路径，不能只写容易混淆的 B01。
- 同一问题的定位加深、修正、重跑与开关对照默认留在同一B目录，以run-id区分；不能每找到一层或改一次配置就新增B。只有出现可独立设判据、独立结项的新问题才分配新B。现有B01→B03→B05→B07保留证据边界，在目录地图聚合阅读，不重写历史编号。
- 旧实验不作为新系列的任务、依赖、默认配置、基线、预算或验收。历史资料只在某个问题确有需要时按来源引用，并重新验证。

| 内容 | 保存位置 | 写到什么程度 |
|---|---|---|
| 活动任务队列 | `docs/infra_exp/01-TASKS.md` | P/Q、状态、前置、下一动作、REPORT 链接；结项移出 |
| 人读实验记录 | `docs/infra_exp/experiments/B00-主题/REPORT.md` | 必要背景、设置/判据摘要、每次测试结果、结论与局限；不写长篇调查或调试日记 |
| 复现索引 | 同目录 `runs/<run-id>.json` | 精确命令、源码/镜像/配置身份、结果字段、证据路径与 SHA；小文件进入 Git |
| 原始证据 | 登记的 Modal Volume 内 `/vol/_audit/infra-probes/B00/<run-id>/` | 完整日志、指标、trace、原始 token、checkpoint 等；不进入 Git |
| upstream 材料 | `docs/upstream/DRAFT-infra-probes-B00-<主题>/1-finding.md` | 需要移交时展开详细背景、问题、根因、方案、影响面与复现说明；链接实验结果，不复制测试流水 |

Volume 必须记录名称或 ID；`/vol` 只是容器挂载点，单有路径不足以找回产物。每次执行使用独立 run-id，各臂有独立写入目录；大模型/共享只读资产可放已有模型目录，但索引必须指向精确身份。记录完成要落盘、持久化并回读核对，不凭 stdout 宣布成功。

REPORT 和小型复现索引纳入 Git 管理，提交仍遵守用户授权。开跑前写设置与判据，跑后及时补结果；结论就地更新，失败/无收益/未测同样保留。报告关闭后保留，不因完成状态搬迁；用户要求的主题改名按上述规则处理；完成项从 TASKS 的执行队列移除，下游依赖改成具体 REPORT/判据链接。原始大产物不要求永久保留：确认无恢复/复验/后续使用/upstream 复现需求且无活动读写者后，按 [Compute 清理规则](../syncopate/05-COMPUTE.md) 直接删除 checkpoint 与临时大文件，先保存必要证据索引，记录保留/删除理由与复核结果。详细说明只在 upstream 文档维护；没有上游发现时不为凑材料创建 DRAFT。

## 2. 先探索真实负载，再立优化任务

分成两个阶段，不能把优化准入条件强加给首次画像：

| 阶段 | 开跑前调查 | 产物与停止依据 |
|---|---|---|
| 真实场景探索 | 谁会采用该组合；最新稳定/main SHA、官方recipe/支持/已知阻塞、模型容量、输入许可与形状、入口和观测 | 不预设bug；真实循环阶段耗时、等待、token/更新与显存画像。无明显瓶颈也可结束，写覆盖与局限 |
| 瓶颈定位与优化 | 必须引用探索run/trace；查相关源码、issue/PR、现有开关/修法；解释准备减少什么成本 | 必要时保留触发组合缩成探针；提出改动/已有方案A/B，回原入口验证收益与代价，无收益也结项 |

每阶段保留UTC日期、检索词/URL、实际release/main SHA、命中摘要、已读内容和网络失败，细目放research.json。初始画像不需要先证明有未解决问题，也不以“问题出现概率低”取消合理真实负载。全面PR排重归upstream，实验组完成足够的准入与已有方案调查。

官方支持或配置存在不代表本组合已验证；不存在功能时先记支持边界。实际需求和瓶颈证明其价值后，功能缺口可成为优化/贡献任务；先查现行替代，不为移植而移植。只证明某配置不支持不能宣称上游bug；main已修则记录版本和复验，不重复提PR。

底层基线是排错参考，不是执行目的。没有真实画像线索不主动启动算子、通信尺寸或逐层数值扫描。固定轨迹/合成tensor仅作后续定位工具；原入口A/B是优化闭环。

## 3. 开跑前必须完整登记

1. 明确是场景探索还是优化；前者登记合理负载与要观察的阶段，后者登记来源run、瓶颈和假设；G只分类。
2. 上游仓库/commit、实验代码 commit/dirty patch SHA、镜像 digest、依赖锁、实际入口；本地修改和旧 overlay 分开。
3. 模型来源/revision、权重/config/tokenizer SHA、full/LoRA/teacher/anchor 身份；输入来源与 shape/token SHA。可控 adapter 说明构造方法，不冒充训练成果。
4. GPU 精确型号/卡数、容量预算、实际进程组和拓扑；CPU/内存、cache/compile 状态；平台缺字段明确未测。
5. 初始画像固定负载/模型/随机种子、有效batch/token和长度分布；优化阶段再登记对照两臂和唯一变量。无需为探索预造一个优化臂；目标变化单独披露。
6. 按阶段登记最低执行健康或受影响的正确性回归、性能/稳定性读数、采样窗口和停止条件；给出读取证据的方法。
7. 优化采用前补受影响机制的正负对照与集成回归；首次探索不要求全套数值/准确率验收。无可测执行/工作量读数不启动；不得跑后放宽阈值。
8. CPU/GPU 次序、卡数、硬超时、总时限、并发、资源费用上限、所属预算账和授权边界。
9. 每次 run 独立目录、写者/进程归属、幂等/正常退出/失败兜底与证据保留方法。

先完成可行的本机语法/输入/假引擎检查，再到 Modal CPU 补目标依赖，再按需要分配 GPU。CPU 测试不能静默 skip 后晋级；与本次问题无关的业务 supply/建库/质量闸不作为通用前置。业务 runbook 被选中时其现有硬闸仍必须遵守，不能为独立探针直接绕过。

## 4. 速度优先，验收分阶段

**初始探索不做业务准确率、工具选对率、学习曲线或全面训推概率对拍。** 保留测速最低健康：模型/输入/资源身份一致、实际token与有效mask数可读、前后向/非零目标更新与权重版本交接真实、无NaN/程序错误、正常退出。已有检查能复用就复用，不为首次画像先造通用正确性平台。若奖励/组内优势全零，登记零有效更新并调整合理负载/奖励接口，不能把weight decay或调用次数当更新。

| 阶段 | 必须证实 | 不要求/不能推断 |
|---|---|---|
| 初始画像 | 工作实际发生且可计量；阶段墙钟/等待、有效token、显存、更新/同步和终态积压 | 不先要求模型答对；不宣称模型质量或全面数值正确 |
| 定位/试改 | 瓶颈证据、真实命中改动、探索性前后读数 | 未回归前不称优化可采用，局部变快不等于整体收益 |
| 优化验收 | 对受影响的梯度/权重/状态/采样/恢复做定向回归，再在原入口比较相同有效工作量 | 不能靠少生成、少更新、截断/丢弃更多或换目标来称等价加速 |

低精度、目标近似、采样或async引入的语义/数值代价，在方案确定后按机制补回归；业务准确率只有确需验证该代价时另行安排。没有回归的速度读数标为探索，不扩大成采用结论。错误身份、NaN、程序异常、坏产物与零有效更新仍停止；不会因为质量WARN打断正常画像。

采用当前受支持、适合生产的合理优化基线；“全关闭”仅用于排错。先初筛画像，有值得采用的改动后，正式A/B至少三个独立可比重复，保留样本、中位数、波动和配对差异；一个分配的三个窗口不冒充三次独立实验。控制硬件/角色/输入与工作量，真实生成分布和固定轨迹结果分开，不以模型回答变短证明加速。

统一有效更新/token预算与终态drain；生成、评分、训练、权重打包/传输/加载、等待和重叠都计量。预热/JIT/启动、轻量遥测和昂贵profiler窗口分开；GPU利用率是信号，不是唯一目标。异步还必须量版本/秒龄、浪费/积压，具体指标见训练专题。采用线结合热点占比、成本与噪声预登记，不统一规定必须快10%。

## 5. REPORT 模板（完整而简洁）

默认控制在一至两屏的摘要加结果表；运行多时结果表可以增长，不以篇幅上限删除证据。字段只写适用内容，尚未测试直接写“未测”。背景调查必须充分，但正文只保留影响立项的结论和关键来源；完整检索索引放小型 JSON，长篇背景/问题/方案解释在需要移交时放 upstream。

````markdown
# infra-probes/B00 · 一个真实场景或证据驱动的优化

状态：场景准备 / 画像中 / 定位中 / A/B中 / 已结论 / 已移交 / 搁置
任务：Qxx；分组：Gx.y；负责人：…；更新：UTC 时间

## 场景与调查结论
两三句话：谁会这样训练，支持/容量是否可行。初始画像不预设错误；优化时引用瓶颈run与现有方案。
查询日期、目标 release/main SHA、关键 issue/PR 链接；继续/停止理由。
完整检索记录：research.json（查询词/URL、命中摘要、适用性判断）。

## 设置与判据
模型/版本、角色和进程组、GPU/卡数、数据形状、真实入口、观测与资源预算；按阶段登记最低健康或受影响回归、对照变量与重复。
复现配置/命令：链接版本固定的配置与 runs/<run-id>.json；不重复抄整份配置。

## 画像、改动与测试结果
阶段耗时/等待和瓶颈证据；没有异常如实写。改了什么、局部解释和原入口A/B之间的关系。
| run-id / UTC | 改了什么 | 结果与关键数值 | 证据索引 |
|---|---|---|---|
| … | … | pass/fail/skip；未测明确标注 | runs/….json |

## 结论与下一步
分别说明正确性、稳定性、性能中本实验测到的部分；适用范围、局限、采用/拒绝/无结论。
累计实际费用与估计分开；异常退出或未回读证据明确说明。
产物收尾：保留/删除的路径、原因和复核索引；需要保留的 checkpoint 写明用途。
upstream：未移交，或链接详细材料及接收状态。
````

小型 `research.json` 保存带日期的检索记录，`runs/<run-id>.json` 保存复现与证据索引；不把整页网页或原始日志塞进 Git。机器索引可用已有格式，但至少包含：完整实验 ID、run-id/UTC、入口命令、源码与 patch SHA、镜像/依赖/配置身份、Volume 身份和证据路径/SHA、判据读数及 pass/fail/skip、费用与退出状态。配置可通过不可变引用复用，不必在每行重复。

这些文件是人工记录约定，**当前尚无自动生成器或 schema 校验器**；选定具体实验时先保证索引实际可回读。全面意味着能复现、能核对、有未验边界，不意味着把所有过程写成文章。

## 6. 实验交付与上游移交

发现异常先判断归属：自有实现/配置、框架、引擎、kernel、驱动或平台。尽量在干净上游最小路径复现；仅自有训练循环出错不得包装上游 bug。

疑似开源问题具备触发条件、版本、最小复现、修前/修后判据和局限后，按 [upstream 模板](../upstream/README.md) 创建 DRAFT。本组不负责正式 PR 考据、成稿、提交或维护者沟通；只有用户要求协调时向对应独立任务投递，实际回复才算接收。

有价值的负结果、现成修法确认和不适用组合都要关项保留。PR 是否合并不由实验组自证，也不以此放宽实验结论。
