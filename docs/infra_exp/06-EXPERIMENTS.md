# Infra · 实验协议

> 本文规定 B 系列实验怎样编号、预注册、落证据和归档。
> 哪个实验先做只看 [01-TASKS.md](01-TASKS.md)。

## 1. 编号

- 新一代实验从 `B01` 开始，按 `B02、B03……` 递增。
- `B` 表示 B200 起步的 Blackwell 系列，不保证实验只在 B200 上运行。
- B300 复核沿用原实验号并加机器臂，或由 TASKS 单独登记；不能覆盖 B200 证据。
- 旧 `E01～E33` 永久冻结在 [4×5090 归档](../archive/infra_exp/legacy-4x5090/README.md)，不重编号、不复用。

## 3. 跑前预注册

每个实验在启动前必须写清：

| 项目 | 必填内容 |
|---|---|
| 问题 | 这次只回答哪一个问题 |
| 兑现物 | 它服务正确性、端到端速度、Serving SLO、成本还是简历哪一项 |
| 前置 | 主线阶段、模型、数据、代码和已有探针是否就绪 |
| 环境 | 镜像、依赖、GPU/拓扑、模型、dtype、shape、并行与缓存 |
| 对照 | before、after、唯一变化，以及为什么两臂可比 |
| 判据 | 正确性、性能、质量和停止线的具体读数 |
| 正负对照 | 什么应当通过，故意改错什么必须失败 |
| 证据 | 每项读数写到哪个 JSON、日志、trace 或 checkpoint |
| 费用 | GPU 型号、数量、预计时长；付费运行的用户授权 |
| 收尾 | 服务如何停止，哪些产物保留，失败如何分诊 |

跑完之后才补阈值，等于没有判据。

## 4. A/B 纪律

- 默认 before 是“当前官方稳定、适合生产的优化已开启”的配置；不用全部关闭的慢配置制造夸张加速比。
- “官方支持”不等于“在本模型、本硬件、本版本上正确且更快”。每个开启的官方开关至少做一次 OFF/ON 认证：真实调用路径有判据、输入/输出或数值差符合预期、端到端收益超过噪声、任务质量不过退化线。
- 本仓库自定义、旧栈遗留或尚未复验的机制默认关闭，只能作为单因素 after。全部关闭臂只用于定位问题，不作为简历主 baseline。
- 一次只改变一个关键变量；组合方案先做拆分消融。
- 两臂使用同一镜像、代码、数据、模型、种子、预热、计时窗口和质量尺子。
- 边跑边修后拼成的多段证据可以验最终机制，但不能验性能；任何一段源码或机器身份变化，整轮最多叫施工 smoke，性能 baseline 必须固定源码重跑。
- 并发 A/B 可以节省墙钟，但每臂写独立目录，不能同时修改共享产物。
- 性能至少报告中位数和离散度；异常跑不能静默删除。
- microbenchmark 先证明机制，真实负载决定端到端是否晋级。
- 冷启动、JIT/AOT、缓存预热和稳态必须分开报告；不能只挑最快窗口，也不能把编译时间静默算掉。
- 若 before 本身不稳定，先修尺子，不解释 after。

## 5. 四类结论

报告只能落入以下一种：

- **采用**：正确性、端到端收益和质量边界全部满足预注册门槛。
- **拒绝**：机制成立，但性能、质量或成本明确不过线。
- **不适用**：目标现象在当前模型、硬件或负载不存在。
- **无结论**：尺子、环境、样本或运行失败，不能把它写成正负结果。

退出码 0、程序跑完或图看起来更好，都不是独立结论。

## 6. 报告最小结构

```text
# Bxx · 标题
结论卡：状态 / 一句话 / 适用边界 / 是否改变默认
1. 问题与兑现物
2. 跑前预测和判据
3. 环境指纹
4. 方法与唯一变量
5. 正确性及正负对照
6. 性能、质量和成本结果
7. 解释、替代解释与负面结果
8. 产物索引
9. 对 TASKS、专题、代码和简历的影响
```

## 7. 跨线结论

实验建议改变主线时，不新建交接文件：

1. 把完整结论和证据落盘；
2. 通过 Codex 独立任务消息工具发给主线负责人；
3. 收到实际回复并消除疑点；
4. 由唯一负责方更新自己的 TASKS 和专题。

工具投递成功不等于对方确认成功。历史消息不是当前状态来源。
