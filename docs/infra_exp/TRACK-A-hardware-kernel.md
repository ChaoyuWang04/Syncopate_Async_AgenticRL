## 0 · 论点（这条线存在的理由）

> **不是「我会写 kernel」，是「我能证明该写哪个 kernel」。**

判据只有两把筛子，任何一道菜进菜单前必须至少过一把：

| 筛子 | 本机的实测形态 |
|---|---|
| **① 负载的稀疏结构** | agent 负载里绝大多数 token 是 prompt 和工具返回，**不进 loss**。**SFT 侧 3.8–4.9%、RL 侧 4.17%（E11 实测，1755 条）——同一量级** ⇒ 这是这类负载的**结构性特征**，不是某个阶段的偶然 |
| **② 硬件的拓扑约束** | 无 P2P、卡间 **6.4 GB/s**（NVLink 的 1/140）。⇒ 通信比计算贵得多，**最好的并行可能是不通信** |

★ **反面教材就在本项目里**：ostinato §4.0 的因果链（前缀缓存不够 ⇒ 量化扩容 ⇒ kernel）
被实测整条推翻——命中率 96.7–97.5%、KV 池只用不到一半、零 preemption。
**当时那道菜没过任何一把筛子，靠的是推演。** 这条 track 的全部纪律来自那次教训。

## 1 · 要解决的实际问题（业务 → 技术）

**业务侧**：第一目标是手游买量投放的全链路闭环 agent，价值指标是 **span of control**
（一个优化师能管住多少 平台×产品×地域×素材 组合）。这个指标直接取决于两件事：

| 业务能力 | 被什么卡住 | 实测证据 |
|---|---|---|
| **agent 能不能自己走完长链路**（多轮工具调用、自己纠错） | 训练时**长轨迹被显存判死刑** | 稀疏投影之前 T=12288 / 16384 **直接 OOM**；bs=2 就 25.54 GB |
| **能不能上更强的模型**（30B MoE 才有的 agentic 能力） | 4×32 GB 且无 P2P，**bf16 62 GB 既装不下、也不敢分片** | 3 卡 FULL_SHARD 1182 s/步 vs 单卡 198 s ⇒ **多给卡慢 6 倍** |
| **迭代速度**（一轮实验多久出结论） | 每步墙钟 | 单卡 91–99 s → 3 卡 32.6 s（已优化一半，剩下的靠这条线） |

**技术侧翻译成两句话**：

1. **算了大量注定要扔的东西。** 模型每到一个位置，都要给词表里 151936 个词各打一个分
   （lm_head 投影）。但 agent 训练里，绝大多数位置**根本不需要这个分数**——它们是
   prompt（规则书、工具文档）和工具返回的内容，**不是模型自己说的话，不进 loss**。
   实测 SFT 每条 5402 token 只有 204 个进 loss ⇒ **那张巨表 96% 生下来就注定被丢掉**，
   而它是全模型最大的瞬态张量、也是 OOM 的元凶。
   **RL 侧同样是 4.17%**（E11，1755 条真实轨迹）：prompt 占 88.3%、工具返回 7.6%、
   模型自己说的只有 4.2%。⇒ 切掉 prompt 省 8.5×，完整按 mask 筛省 24×。
2. **搬运比计算贵得多。** 这台机器四张卡之间没有直连（P2P 全关），
   所有数据要绕主机内存，只有 6.4 GB/s。**任何"把模型切开、每步再拼回来"的做法都是灾难**
   ——实测多给卡反而慢 6 倍。

## 2 · 解法，以及**为什么不是别的解法**

### 2.1 针对「算白算」→ 稀疏化最后一步（E11）

**做法**：先只算到 hidden，按 `response_mask` **挑出真正需要的那几行**，
只对它们做 lm_head + logprob/entropy。**数学上完全等价，不是近似**——
被丢弃位置的梯度本来就恒为 0。

| 备选方案 | 为什么不选 |
|---|---|
| **① 用 verl 自带的 fused kernel**（NVIDIA `linear_cross_entropy`） | **已经在用了**（省了 5.0 GB），但它是**稠密**的：函数签名里根本没有 mask 参数，对整条打包序列的每个 token 都算。它解决的是「不物化整张表」，**没解决「不该算的别算」** |
| **② Liger kernel** | 同样是通用实现，同样不知道我们的 mask 结构 |
| **③ 先按 mask 切片，再喂给现成的 kernel** ★ | **这是必须先试的对照组，不是备选**——如果切片就能拿到大部分收益，**就不该自己写 kernel**。本项目的教训：「一行开关」的对照组经常就是答案（ostinato §14.1） |
| **④ 自己写 masked fused kernel** | 只有在 ③ 证明不够（比如切片本身的 gather/scatter 开销吃掉收益、或反向传播路径断了）时才做 |
| 上游为什么不做 | 通用 RL 是单轮数学/代码，response 占 50%+，**他们没有这个问题**。我们是 prompt 3.2k + 工具返回一大堆、模型自己说的很少 ⇒ **负载画像决定该优化什么** |

### 2.2 针对「搬运贵」→ 用量化换取「不通信」（E07）

**做法**：把冻结的基座压到 4bit（约 17 GB），**每张卡放完整一份**，纯数据并行，
每步只同步 LoRA 的 132 MB。

★ **这是这条线里量化的唯一正当理由：量化的目的是省通信，不是省显存本身。**
（单卡时代量化是为了省显存换 KV 池——那个动机在 4 卡上**已经塌了**，别再引用。）

| 备选方案 | 每步训练侧通信（推算） | 为什么不选 |
|---|---|---|
| **A · FSDP 分片** | 每 micro-batch **~90 GB** 跨卡 all-gather 冻结基座 | 实测已证：3 卡比单卡慢 6 倍。6.4 GB/s 上 ⇒ 每 micro-batch 15–20 s 纯通信 |
| **B · CPU offload** | 与 A 同量级 | 「反正都过主机内存」——本机特有的等价性，值得实测证明，但不解决问题 |
| **C · 4bit 复制** ★ | **~132 MB/步** | **少三个数量级。** 代价是 4bit 基座质量 + 训练侧也引入量化 ⇒ 必须过任务级尺子 |
| D · TP / PP | 每层多次 all-reduce，通信频率最高 | ① 要 Megatron/torchtitan 后端，**没装且 sm_120 有风险**；② 无 NVLink 上 TP 大概率净负 |

### 2.3 针对「这块卡到底什么能点亮」→ 能力探底（E13）

sm_120 是消费级 Blackwell：**有原生 FP4/FP8，没有 TMEM**（数据中心 Blackwell 才有）。
⇒ 编程模型退回 Ampere 式 `mma.sync`，**Triton + inline PTX 全覆盖，没有够不着的指令**。
但生态几乎没人点亮它——Triton 的 `tl.dot_scaled` 在 5090 上会**静默退化成 bf16**（triton#7550）。
⇒ 「这块卡上什么是真的、什么是假的」本身就是没人做过的测量。

## 3 · 怎么衡量（benchmark 设计与指标）

**三层尺子，缺一层不算完成**（这是本项目区别于全生态「只报 PPL」的地方）：

| 层 | 量什么 | 判据 |
|---|---|---|
| **微观 · 算子** | 与朴素实现**逐位对拍**：loss 差 < 1e-4、grad `allclose(rtol=1e-3)`；单算子 ms/token；峰值显存 | **先证明等价，再谈快慢**。不等价的加速不算 |
| **中观 · 训练步** | `update_actor` **ms/token**（按 token 归一，否则打包会让你比错）；每步墙钟；`max_memory_allocated`；**能训的最大序列长度 T_max** | 同一配置各跑三遍取中位 |
| **宏观 · 任务** | 冻结 EVAL 128×8 **配对**比较（`compare.py` 自报 MDE ≈ 0.05）；26 个 cap 的**构成**；决策位熵；RL 侧另加 **ESS** | 只报吞吐不报任务精度的优化**不算完成** |

**分母纪律（代价已经付过）**：
- **同一 trace 重放，不用合成负载**；优化前后各跑三遍取中位；
- **加速比必须有同机分母**（目前 colocate 同机基线还欠着 → E08）；
- **一次只变一个变量**——曾经同时改 DDP 和 dynamic_bsz，1.36× 的收益分不出是谁的，
  补了 2×2 才发现一个 ÷3.0 一个 ×2.2、**方向相反**，差点把倒退当收益收下；
- **性能数字必须独占 GPU**：竞争 + 满载 2.3 kW 降频（E00 未测）会污染一切对照。

## 5 · 兑现物（简历那一段的骨架，〔 〕待实测填入）

- **负载画像驱动的稀疏计算**：agent 负载的监督密度仅〔SFT 3.8% / RL 实测〕，
  而训练栈对全部 token 物化 logits。SFT 侧自写稀疏投影（数学等价非近似，4 条对拍测试）
  峰值显存 16.94→10.40 GB、T=12288 从 OOM 到可训；RL 侧〔E11 实测〕，
  与 verl 内置（NVIDIA linear_cross_entropy）/ Liger / 朴素切片同台跑分〔结果与归因〕。
- **拓扑驱动的量化**：在无 P2P、卡间 6.4 GB/s 的机器上，分片的 all-gather 代价
  〔E07 实测〕远超复制 ⇒ **量化的动机是省通信不是省显存**；
  4bit 基座复制把每步训练侧通信从〔实测 GB〕降到 132 MB。
  精度侧不止 PPL：任务级配对回归（MDE 0.05）+ RL 采样分布 ESS〔实测〕。
- **sm_120 能力探底**：Triton `tl.dot_scaled` 静默退化复现 / FP8 GEMM roofline
  〔实测 TFLOPS〕/ FP4 `mma.sync.m16n8k32` inline PTX〔实测〕。
- **执行层消泡**：nsys/ncu 定位 decode 空转根因，逐项归因〔E14 表〕。

## 8 · 这条 track 特有的坑

1. **别为不存在的问题写 kernel。** §0 的反面教材。**开工前先问它过了哪把筛子。**
2. **「一行开关」的对照组经常就是答案。** ostinato §14.1 结算：军火库清空拿到的收益
   （fused kernel −5.0 GB、停搬运）**比原计划里任何一道手写菜都大**。

4. **「简历/手艺」价值和「项目关键路径」价值可以同时承认，但不能混在一起排优先级**（ostinato §16）。
