## T1 · Smoke 质量收口与固定源码复验

**已完成的机械前置**：B02 已证明真实 v16 数据能从 SFT 连续传到 OPD，所有训练段都有真实更新和可加载产物。证据见 [B02 报告](../../_audit/infra/B02/REPORT.md)。

**当前目标**：修掉 B02 暴露的质量问题，并在 infra 冻结胜出设置后，用同一源码再跑一遍干净 smoke。

**唯一入口**：[scripts/v16_pipeline.sh](../../scripts/v16_pipeline.sh)，profile 使用 `smoke`。

| 顺序 | 工作 | 当前状态 | 完成条件 |
|---|---|---|---|
| T1-1 | 修 RL 未闭合/重复思考 | 队首 | 先审计实际 prompt 和 B02 原始轨迹；修复后 2-step smoke 的健康闸全绿，响应截断质量闸不再报 25%；不能靠缩短预算藏掉问题 |
| T1-2 | 修 Exam 质量缺口 | 等 T1-1 | 对 6 个判卷失败和 1 个机器壳终答逐项归因；修复不破坏 40/40 运行、身份和行为记录；candidate 门槛另行预注册 |
| T1-3 | 解释 OPD 短评测退化 | 等 T1-1 | 解释 9 次工具错误和多样性 5/8；用多于一次真实更新的诊断确认问题来自数据、学生行为还是蒸馏目标，不能拿一更新分数做收益结论 |
| T1-4 | 固定源码 clean smoke | 等 T1-1～3 与 infra B03～B06 | 同一源码和冻结设置完成全链；所有健康闸通过，质量 WARN 要么关闭、要么有阻止 candidate 的明确任务；证据与 run id 唯一绑定 |

T1 只有在以下条件全部满足后才能关闭：

1. 后一阶段读取前一阶段产物，不依赖裸底座、正式目录残留或人工临时参数。
2. 每一阶段健康闸全绿并能被下一阶段真实加载；质量 WARN 不得被写成 PASS。
3. OPD 至少产生有效蒸馏步，不能用几乎全部跳步冒充通过。
4. clean smoke 使用同一源码与冻结配置；结论只能写“真实 v16 全链 smoke 通过”，不能写“候选模型通过”。

## T2 · Candidate 训练与质量验收

**前置**：T1 关闭；infra B03～B07 完成并冻结胜出组合；用户批准候选运行计划、费用和预注册门槛。

进入候选训练前还要关闭这些口径：

- 根据 v16 首次实测登记六桶正式份额带宽，并决定是否启用严格模式。
- 确认 L1 历史复用、SFT 空格保底和“机器词进入人话”是否需要新门禁。
- 用 v16 首次正式 Exam 读数重新登记考场门槛。
- 逐项冻结 candidate 的停止、晋级、回退和证据路径。

**完成条件**：候选 SFT、RL、OPD 与冻结评测全部按预注册规则结束；结果被明确判为晋级、回退或无结论。

## T3 · Serving 正式验收

**前置**：用户确认验收机器、模型端点、公开范围和演练权限。

验收范围：

- 在当前 Celery/Redis/PostgreSQL 栈重跑真实负载与连接预算。
- 真正演练停队列、warm drain、回滚和恢复，不只检查命令存在。
- 演练模型权重恢复；真人灰测前确定 PostgreSQL 备份策略。
- 重建并检查前端，确认反馈入口和版本信息可用。
- 对外开放前补齐 API、org、写工具和模型调用的并发限制。
- 用干净环境生成新的 SLO 基线，不能沿用旧机器或污染开发库的读数。

**完成条件**： [07-SERVING.md](07-SERVING.md) 的发布清单全部得到“通过”或带明确触发条件的“当前不适用”，且关键演练有落盘证据。
