# Syncopate · 15 — 三桶泄露门禁

> 写于 **2026-08-17**（v13 第一次评测当天查出来的）。
> **每个大版本重切三桶之后必跑**，不过就不许拿这份评测当基线。
>
> ```bash
> python scripts/check_data_gates.py --batch data/batches/v13 --split-dir data/splits/v13
> ```
>
> 判据实现：`syncopate/pipeline/leakage.py`（**真相来源**）
> 构造保证：`syncopate/pipeline/split.py`（按泄露组做分层取样）

---

## 0 · 事情是怎么被发现的

切分报告一直写着「三桶零重叠 ✅」，而且那不是空话 —— 它用 **SHA-256** 算
「完整渲染的 prompt + gold 答案 + behavior」的指纹，实测 0 重叠，我还独立复算过一遍。

**但换个角度查就露了**：

```
ATTR_0001 [EVAL]  「我们在 GB 想扩量。真人出镜这个素材特点到底有没有用？」
ATTR_0048 [SFT ]   题面一字不差，gold 答案也一字不差（lift 0.1791）
```

两条的 `campaign_id` 不同 ⇒ 完整 prompt 不同 ⇒ **哈希不同 ⇒ 检查通过**。
而模型要答的那件事完全一样 —— **把 SFT 那条背下来，不读世界也能答对 EVAL 这条。**

**v13 实测：62 / 278 = 22.3% 的 EVAL 有这样的孪生。**

> ⇒ 和 D5「句式泄露档位」是同一条教训：
> **一个判据只覆盖了它作者当时想到的那种形状。**
> `content_hash` 想的是「两条 case 完全一样」，没想到「只有无关的 ID 不一样」。

---

## 1 · 两级判据

| | 键 | 适用范围 | 性质 |
|---|---|---|---|
| **L1** | (题面**原文**, gold 答案) | **所有模板** | 硬门禁 |
| **L2** | (题面**句式**, gold 答案) | **除豁免模板外** | 硬门禁 |

「句式」= 用 case 自己的 `entities` / `context` 把实体和数值抹掉之后的题面
（不猜正则 —— 模板往题面里填的东西本来就都在那两个字典里）。

### 1.1 ★ L2 的模板豁免，必须显式列出来

```python
L2_EXEMPT = {
    "CHAT": "不需要查数据的能力询问/闲聊，答案就该由问法决定",
    "CLAR": "关键槽位缺失，答案是「问哪个字段」，由问法决定",
    "REJ":  "越权/越域，答案是「拒绝 + 类别」，由问法决定",
}
```

**这三类的可记忆性是我们要训的能力，不是漏洞** ——「帮我把竞品预算调低」永远该是
`reject/unauthorized`。不豁免的话 L2 会把它们全判成泄露（实测受影响面从 22% 虚涨到 48%）。

⚠️ **豁免要写清为什么，不许"因为它红了就加进来"** —— 空着的门槛应读作"无法判定"。

### 1.2 ★★ 两类结果性质不同，不能混成一个 passed

```
涉及 EVAL 的泄露    = **有效性问题**（评测数不可信）        ⇒ 硬门禁，必须 0
SFT ∩ RL 的重复     = **效率问题**（RL 在学 SFT 已教会的，
                       组内方差为 0 ⇒ 零梯度）              ⇒ 报出来，不阻塞
```

v13 修完：EVAL 受影响 **0**；训练池内仍有 L1 40 组 / L2 77 组 —— 那是零梯度率的一个已知来源，
留给 RL 侧优化，不该拿来卡住评测。

## 2 · 修法是构造保证，不是事后查

**按「泄露组」做分层取样，组是原子的**：同一个泄露键的所有 case 要么整组进 EVAL，
要么整组不进。

⚠️ 试过一版「先按 case 选完，再把孪生拉进来」—— **EVAL 从 278 膨胀到 507**
（拉进来 229 条），SFT/RL 被抽干。按组取样则规模基本不变。

```
v13 修复前   EVAL 278 / SFT 511 / RL 881   受影响 EVAL 62 (22.3%)
v13 修复后   EVAL 343 / SFT 503 / RL 824   受影响 EVAL  0
```

EVAL 从 278 涨到 343，是把孪生整组收进来的代价 —— **换来的是这 343 条真的在考读世界。**

---

## 3 · 为什么这件事非查不可

这份冻结 EVAL 的审计**接下来要当 M7 第二跑的基线**。基线掺水两成，
后面所有配对比较都跟着歪 —— 而配对 MDE 只有 0.013，两成噪声足以淹掉真实效应。

⇒ **「三桶零重叠」这句话以后要连口径一起说**：
是 `content_hash` 口径（完整 prompt 相同）还是 L1/L2 口径（同一道题）。
两个都过才叫零重叠。

---

## 4 · 别再重新讨论的

- **L2 必须分模板豁免**，而且豁免要写理由（§1.1）。
- **EVAL 泄露是硬门禁，训练池重复只是警告**（§1.2）—— 别把后者也拿来卡门。
- **修法是按组取样**，不是"选完再拉孪生进来"（§2）。
- `content_hash` 那条检查**保留**，它挡的是另一种形状（完全相同的 case）。
