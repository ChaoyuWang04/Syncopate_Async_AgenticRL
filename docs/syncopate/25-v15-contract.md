### 1.1 · 这条路对不对：外部做法对照（08-29 调研）

> Chaoyu 的问题：小模型可以把意图穷举成 tool，**大基模没法穷举，那它们的可验证奖励靠什么？**
> 结论：**没有人只用一种奖励。业界是分层的**——能形式化的走规则，不能形式化的走判分模型，
> 并且靠 SFT/RL 交替把两者缝起来。我们做的"意图工具化"在文献里有专门名字，且我们规模够小、正好适用。

```
① 可验证奖励（RLVR）本来就有边界
   数学/代码这种"对错可判"的领域效果最好；开放域评价是多标准的细粒度判断，
   二元正确性signal 不够用——这是公认的限制，不是我们的特殊问题。

② 不能形式化的部分，主流解法是「评分量表当奖励」（Rubrics as Rewards）
   给每道题配一份带权重的检查清单，让 LLM 判分器逐条打分再聚合成标量。
   报告收益：HealthBench +31%、GPQA-Diamond +7%（对照 = 直接让 LLM 打 Likert 分）。
   ⇒ 大模型的"可验证"不是靠穷举 tool，是靠**把模糊标准写成可逐条核对的清单**。

③ ★ 和我们最像的一篇：Abstain-R1（可验证 RL 做"该不答就不答"+追问）
   它的奖励是**两段式**，正好回答「自然语言说了 defer 该不该给分」：
       结构分 0.3   规则判：输出里有没有那个**结构标记**（它用 \boxed{I don't know}）
       语义分 →1.0  LLM 判分器判：追问的**内容**和参考追问语义对不对得上
   两个配套发现直接对我们有用：
     · 判分器要**故意用小而严的**（3B）——宽松判分器会被刷分；严到宁可错杀
       （跨域实测拒掉 94 条其实正确的澄清）也不放水。
     · **必须先 SFT 冷启动**：没有冷启的模型根本达不到严判分器的门槛，
       于是"只学标签不学能力"这条路被堵死。
   ⇒ 结构与语义**不是二选一**：结构标记当底分（便宜、精确、不可刷），
     语义判分当增量（贵、模糊、但覆盖形式化不了的部分）。

④ 把开放任务改造成"自带判据的环境"是一类公认手法
   （任务变换出自我可验证奖励 / 开放任务重述成可验证选择题）。
   **我们的 session.* 工具化就是这一手**——把"我要等/我要问/我要拒"从
   一句话变成一个有 schema 的动作。它成立的前提正是 Chaoyu 说的：**意图空间小**。
   基模穷举不了，所以它们只在小闭域这么干，开放域交给②③。

⑤ 「是不是都靠 SFT→RL→SFT→RL」——是的，这就是前沿配方
   DeepSeek-R1 的四段：冷启 SFT（长 CoT，先立格式）→ 规则奖励 RL（准确/格式/语言一致）
   → 拒绝采样 SFT（把 RL 的好样本收回来 + 掺通用数据）→ 全场景 RL（规则奖励 **+**
   偏好模型奖励，一起上）。
   ⇒ 分工是清楚的：**SFT 管冷启动与格式稳定，RL 管把能力边界推出去**；
     **规则奖励管能算对错的，模型奖励管风格与帮助性**。最后一段两种奖励是并存的。

对本项目的三条落点
  a) 我们把行为工具化是对路的，且**恰恰因为我们域小**才敢这么干（不是通用解法）。
  b) Chaoyu 的「自然语言说了 defer 也该得分」在文献里有现成形状 = ③ 的两段式。
     本版把它写成 R0 的**可选第二读数**（§4-R0 门槛②b），先量、再决定要不要进 reward。
  c) 「有些东西天生不适合形式化」是对的——所以 v15 只把**五个行为**形式化，
     "说人话"始终不进规则判分，只走盲评（N1 的判法就是正则扫壳，不判语言质量）。

出处：Rubrics as Rewards(arXiv 2507.17746) · Abstain-R1(arXiv 2604.17073) ·
TruthRL(arXiv 2509.25760，三元奖励 +1/0/−1 降幻觉 19.1%) · RLSVR(arXiv 2607.23802) ·
DeepSeek-R1(arXiv 2501.12948)。链接见 22 §决策附录同日条目。
```

## 2 · 目标定义：「Claude Code 一般自然」的五条可验收性质

> Chaoyu 的原话是模糊概念，此处定成可判定性质；R5/R6 的门槛直接引用 N 编号。

```
N1 纯净终答   给人读的文本里零机器语法：无 JSON 壳、无代码块包裹、无字段名（summary/
              behavior/reply 等词不以字段身份出现）。判定：终答文本正则扫描零命中。
              ⚠️ N1 只判"有没有机器语法"，**不判语言质量**——后者只走盲评。
N2 结构单通道 一切机器可读结构只出现在 <tool_call> 里（业务工具 + session.* 信令工具）。
              判定：解析器对全量输出无「壳格式」分支命中。
N3 按需思考   <think> 可见可折叠（前端已具备）且触发合理：难例思考率与简单题思考率
              拉得开（量化带见 R5 门槛）。
              ★ 机制前提（探针 P3 实测）：**必须切到 think-on 渲染**。think-off 时模板会在
              生成提示里把 think 块**预先关闭**（`…assistant\n<think>\n\n</think>\n\n`），
              模型在结构上没有思考的机会——N3 在 think-off 下不是"做得差"，是**不可能**。
N4 行为即动作 等待/澄清/拒绝是显式动作（session.* 调用），系统可编排（挂起/等补充/终止），
              前端渲染成对应卡片；「标签当装饰」在结构上不再可能——不调工具就没有行为。
N5 一份契约   训练=评测=部署同一渲染与解析（现状已如此，v15 保持）；任何分叉必须像
              F-5 那样显式登记理由。
```

## 3 · v15 契约 spec（精确定义，R1 的实现依据）

### 3.1 · 三通道与信令族

```
三通道
  think 段     <think>…</think>（Qwen3 原生）★ v15 起 **think-on 是训练/评测/部署的默认**，
               且**每个 assistant 轮都显式写出 think 段**（有内容 or 显式空块，二选一，
               比例即 N3 的旋钮）——理由与实测见 §3.2
  tool 段      <tool_call>{"name":…,"arguments":…}</tool_call>（业务工具照旧）
  终答段       纯自然语言文本（一到数句人话），或一次 session.* 信令调用后的收尾话

session 信令工具族（注册进 ToolRegistry，handler 为零副作用 ack；runner/runtime 特判终止语义）
  session.defer    {reason: str, recheck_after_days: int}        终止性·runtime 可挂起复查
  session.clarify  {question: str, missing_fields: [str]}        终止性·runtime→waiting_for_user
  session.reject   {reason_code: enum[out_of_scope|unauthorized|policy], explanation: str}
                                                                  终止性·runtime 终止并审计
  session.report   {…按 case 的 answer schema 生成…}              非终止性·机器可核数字/标签
                                                                  的结构化通道（承接原 answer_fields
                                                                  机器字段；summary 字段废除）
终止语义
  轨迹结束 = 助手输出不含任何 tool_call 的纯文本轮，或调用了终止性 session.*。
  空文本终答 = 解析错误（防空壳终答老病，判据沿 P0-2 内容口径）。
行为推导（分桶/审计/判分用——由判定器推导，不再要求模型输出标签）
  有业务 tool_call 且以纯文本收尾        → tool_call（办了事）
  无任何工具、直接纯文本                  → answer
  调 session.defer / clarify / reject   → defer / clarify / reject
  ⇒ verifier_engine:322 的行为闸逻辑不变，只换 trajectory.behavior 的推导来源。
prompt 面
  step_user.txt 的「本次结论需要给出的字段」段废除，替换为 session.report 的工具 schema
  （runtime 与训练同一份最小口径——顺带根治 L1 标签泄漏家族）。
```

### 3.2 · ★ think 段的契约（CoT 修法；原归因已被探针推翻）

```
原以为（24 §7 与本文初稿）  850/890 行的空 think 块进了 SFT 监督 ⇒ 把"别思考"训进去了。
实测（探针 P1/P2）          ✗ 错。真实分布是：
    · 849/890 行（95.4%）的空 think 块在**提示段**（loss_mask=0，**没有梯度**）
    · 只有 41 行（4.6%，全部 bucket=cot_hard）的 think 块在监督段
    · 而这 41 行内部：监督到的 think 块 **295 个空 / 41 个非空 ⇒ 空块占 87.8%**
      （每行 7–9 个轮次，只有最后一轮带教师推理 561–1159 字符）

⇒ 真机理是两条，且和"比例低"无关：
  ① 结构性剥夺（占 95.4%）：think-off 时模板把 think 块**预先关闭**再交给模型生成
     （P3 实测：提示以 `…assistant\n<think>\n\n</think>\n\n` 结尾）。
     模型不是"不想思考"，是**结构上轮不到它思考**，两个方向都没有梯度。
  ② 反向监督（占 4.6% 的 CoT 行内部）：本该教思考的那批行，88% 的监督 think 块是空的——
     等于在教「调工具的轮次不要思考，只在最后一轮想一下」。
  ③ 部署侧还叠了一层分布外：dev 栈用 SYNCOPATE_RUNTIME_THINKING=1（think-on）
     去跑一个 think-off 训出来的模型 ⇒ 它从没在"没有预关闭块"的上下文里生成过。

修法（必须两件一起做，只做一件会更糟）
  A. 契约切 think-on：`rollout_budget.ENABLE_THINKING` 从"探针开关"升为 v15 默认；
     `launch_rl` 的训练路径硬拦要**显式解除**（它的前置条件原文是「think-on 训练要等
     带思考的 SFT 数据」——R2 产的正是这批数据，条件到此才成立）。
  B. `sft_replay.gold_script()` 为**每个** assistant 轮显式产出 think 段：
     难例填教师推理，简单轮填显式空块 `<think>\n\n</think>`。
     ⚠️ 只做 A 不做 B 的后果（探针实测）：think-on 下监督段直接以 `<tool_call>` 开头、
     **一个 think 块都不出现** ⇒ 变成主动训练"永不思考"，比现状更糟。
  ★ 可行性已验（探针 P4）：think-on 下 `tests/train/test_rollout_loop.py` 的
     SFT/RL 逐 token 同构测试 **7 passed** ——同构靠"只有一条代码路径"保证，与开关无关。
     这是修法最大的风险项，已排除。
  代价（必须一起进预算）：MAX_RESPONSE_LENGTH 2048→8192 ⇒ R6 的 RL rollout 显著变慢
     （infra 早标注过「CoT 后 rollout 变慢」）；max_model_len 5120+8192=13312
     ≤ 现服务 14336，**服务侧不用改**。
```
