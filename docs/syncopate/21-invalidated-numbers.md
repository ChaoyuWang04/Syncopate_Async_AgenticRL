## 0 · 三十秒读懂

```
七个根因把 2026-08-14 至 08-18 之间**所有 RL 训练的实测数字**污染了。
其中两个是基石级的：
  B1  三个 trainer rank 没有同步梯度  ⇒ 每次更新只用 1/3 的数据
  B2  trainer 的权重**从没推给 rollout engine** ⇒ rollout 全程用同一份权重

⇒ 「异步」「陈旧度」「ESS 崩塌」「lr 被夹住」这一整套叙事，**量的是这两个 bug**。

✅ 但**不是所有东西都废了** —— §3 列了仍然有效的，同样重要：
   过度作废会让我们把好不容易量到的静态事实也一起扔掉。
```

## 1 · 七个根因

| # | 根因 | 它污染了什么 | 出处 |
|---|---|---|---|
| **B1** | **三个 trainer rank 没有同步梯度**，各训各的 LoRA | 每次更新的**有效数据量 = 1/3**；存下来的 ckpt 只是 rank_0 那一份 | `../infra_exp/E21` |
| **B2** | **trainer 的权重从没推给 rollout engine** | `π_rollout` 全程钉在 π₀ ⇒ **所有「陈旧度 / ESS / IS」的数字量的是一个无界的 bug**，不是设计参数 | infra 2026-08-18 |
| **B3** | **配对比较的两端不是同一个起点模型**：基线跑在「裸基座+SFT adapter」，RL 起点是「合并后的 SFT 模型」 | 所有 SFT↔RL 的配对差值、逐题计数、逐模板涨跌 | `18 §11.2` |
| **B4** | **训练与评测的长度预算不一致**（3584/1536 vs 5120/2048） | 训练侧的截断率、`response_length`、`max_steps_cap` 命中；**评测量到的截断率不能套到训练** | `20 §P0-1` |

| **B6** | **合并模型丢了 36% 的 SFT 增量**（bf16 存不下小增量） | 「合并模型」与「基座+adapter」不等价 ⇒ B3 的成因 | `18 §3.3` |
| **B7** | **导出的 adapter 只是 rank_0 一份** | 所有基于 `models/Qwen3-4B-rl-v13-s110/lora_adapter` 的评测 | `18 §4` |
