## 2 · ★★★ 共同形状：**一个「两个东西应当相同」的前提，没人验，违反时不报错**

把六条并排看，它们不是六个独立的疏忽，是**同一句话的六个实例**：

| # | 「应当相同/完整」的那两个东西 | 实际 |
|---|---|---|
| ② | 训练侧算的 IS 权重 ↔ 一个可用的估计量 | 67% 被截断压平 |
| ③ | rank0 的梯度 ↔ rank1 的梯度 | 各不相同 |
| ④ | 合并后的权重 ↔ 基座 + 增量 | 逐位等于基座 |
| ⑤ | 存进 bf16 的增量 ↔ 想存的那个增量 | 残差 0.87 |
| ⑥ | 基线审计的起点 ↔ RL 的起点 | 差一个 36% 的扰动 |
| ⑦ | 瘦身报告说回收的量 ↔ 磁盘上真的回收的量 | 差 3 倍 |

⇒ **它们全都不报错。** 形状对、能加载、能训、指标好看、曲线漂亮。
⇒ 这正是本项目记了十几次的那条：**「机制在，但没接上」的最新一批变种。**

### 2.1 为什么这一批特别难发现 —— 三个层次

```
第一层  没有判据          从没人写下"这两个应该相同"                    ③④⑥
第二层  判据量错了对象     0.3 是比例不是绝对数 · 瘦身按单个文件报量      ①⑦
第三层  判据本身偏乐观     verl 报的 ESS 是**截断之后**算的，
                          而且截断比例越高它越乐观                       ②
```

★ **第三层最贵**：它会产出一个具体的、看起来合理的数字，让你以为量过了。

### 2.2 ★ 这一天所有的发现，没有一个来自 code review

```
③ 是一句防御性断言炸出来的（写它的人本来只是想防"读错分片"）
②④⑤ 是**逐位比对产物**比出来的
⑦ 是 du 出来的
①⑥ 是**读我们自己抄下来的原文 / 审计文件的 label** 读出来的
```

⇒ **一次都没有靠"读代码看着不对"。**
⇒ 而且第 ③ 条的发现方式是可复制的：**成本几乎为零的一句断言，抓到了全项目最大的 bug。**

## 3 · 它们互相放大 —— 「学不动」是好几条叠出来的

```
名义上   每次更新用  6 题 × 8 采样 = 48 条序列
③ 梯度不同步        ⇒ 每个 rank 只看 16 条
② 序列级 IS 崩塌    ⇒ 剩下的又有 67% 被压平
⇒ **每次更新真正起作用的 ≈ 16 × 0.33 ≈ 5 条**
```

再叠上 ⑥：那 5 条学出来的东西，**还是拿一个错的基线去比的**。

⇒ 「跑完一整遍数据集能力几乎没变」这个现象，**至少三条都有份**，
   而我们此前把它整个归因给了「lr 被 ESS 夹住」。
⇒ ★ **归因做完会有一种"已经解决了"的错觉** —— 这条记忆（`observed-needs-an-owner`）
   这次以更贵的形式复现了：**我们不是没人接手，是接手的人在修一个不是主因的东西。**

## 4 · 哪些结论作废了（引用前必看）

| 结论 | 状态 |
|---|---|
| 「lr 被夹在两堵墙之间」（`16-m7b` 的核心叙事） | 🔴 **两堵墙都不是原来说的那个** —— 一堵是 ②（估计量），一堵是 ③（1/3 数据）。要重写 |
| M7-b 的全部评测数字（85 涨/70 跌、写桶 +0.057、`unauthorized_write` 91→128） | 🔴 跑在 **rank_0 的 1/3** 上，且基线不可配对（⑥）⇒ **幅度全部要重测**，方向存疑 |
| 位移 0.0487% / 0.10% / 「一个 epoch 只更新 109 次」 | 🔴 次数没错，**每次的数据量要 ×3** |
| E20-a「token 级 IS 让 ESS 回到 1.000」 | 🟡 **比值大概率仍成立**（两臂同样受 ③ 影响），绝对值要复核 |
| E17 的 KL A/B（省 12.7%）· B10/B19 的代价曲线 | 🟡 吞吐类结论受影响小，但**精度侧一律要重来** |
| B11 拓扑放置差 1.6% · B20 dynamic_bsz 无收益 · E18 对齐悬崖 · E16 FP8 1.9× | ✅ **不受影响**（纯硬件/通信测量，与训练正确性无关） |
| 数据侧（v13 三桶、多样性门禁、泄漏门禁、评测分片合并） | ✅ **不受影响**，已逐条验过（`18 §7`） |

数据生成 / SFT（单进程单卡）/ merge / eval（4 个独立单卡进程）**全都没有集合通信**。
已 grep 全仓库确认（`18 §11.4`）。

### 5.1 ★ 一条选断言的原则（这次最值钱的方法论）

> **断言要写在「两个东西应当相同 / 某集合应当完整」的地方，
> 不要写在「这个数应该在某个范围里」的地方。**

前者非黑即白、不需要阈值、不会因基线漂移而失效；
后者就是本项目一路踩过来的「空门槛 / 门槛太宽 / 门槛量错对象」。

⇒ 对照本文：③④⑥⑦ 全是前者，一验就炸；而 ①（ESS 0.3）正是后者的典型 ——
**它写满了、真的在跑、真的报了个数，只是量的不是我们以为的那件事。**

### 5.2 还欠的三条防线

```
⬜ Q1 权重同步之后，vLLM 里的权重 == trainer 里的权重（只验过"没 OOM"）
⬜ Q2 评测走 vLLM LoRA、训练走合并权重，两条路径从没验过等价 ——
      而 ⑤ 刚证明它们**在数学上就不等价**（差一个 36% 的扰动）⇒ 这条已经不是"待验"，是"待量"
⬜ Q3 按 rank 分别打 log_ppl_diff ——
      ③ 之下 rank1/2 的 π_old 已偏离推给 vLLM 的那份，
      E20「230× 里 229/230 来自陈旧度」这个归因**很可能要重写**
```

★ **Q3 只要一行 print，但它可能改写 E20 的主结论** —— 排在重跑之前。
