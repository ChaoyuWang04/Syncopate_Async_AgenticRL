## 1.4 ★★ 兑现：M7（2026-08-14，fully_async / 150 步 / 起点 v11-e1）

**四段式记账，推翻的预测不删。**

### P1「涨的主要是 CRE / MISS / BUD」—— **部分推翻**

- **原猜想**：低分且有梯度的那批涨得最多。
- **实测**：BUD **+0.055** ✅、FAIL +0.046、RAG +0.030；但 **CRE −0.026** ❌、
  FRESH −0.062、MISS 仅 +0.006。GEO 纹丝不动（0.246→0.248）。
- **推翻后**：「低分 + 有梯度」不足以预测涨幅。FRESH 掉得最多，而它**基线并不低**（0.882）——
  说明 RL 会**动到本来做得好的题**，方向不是单调向上的。
- **教训**：预测涨幅要按「组内方差」分组，不是按「均分高低」分组。

### P9「分布漂移恒等于 0」—— **成立，但理由和写的时候想的不一样**

- **原猜想**：sync 有 barrier ⇒ 构造上不可能漂移；async 下应该测到非 0。
- **实测**：**async 下也是 0.000**，下发 7200 = 训练 7200，一条不差。
- **推翻后**：真因是 **`partial_ratio = 0`** —— 没有任何一条轨迹跨越策略版本边界。
  轨迹太短（4.5 工具步、~700 token）相对同步周期（4 步 ≈ 300 s），根本碰不到边界；
  且 `--partial-rollout True` 是**续跑不是丢弃**。⇒ 不是"没测到漂移"，是**这一跑里没有漂移可测**。
- **教训**：① 想让这条线有内容，要调大 `--latency-scale` 或缩短同步周期，
  **让轨迹真的跨越版本边界**；② `record_dispatch` 记在轨迹**末尾** ⇒ 「下发」实为「跑完」，
  「尝试过但从未跑完」的轨迹这把尺子**看不见** —— 要测那个得在 rollout **开始时**也记一笔。

### 停止条件全部通过，且判据都实跑验证过

`ESS 0.74–0.88`（键名是 `rollout_corr/rollout_is_eff_sample_size`，**不叫 ess**）/
决策位熵 0.027→**0.072**（升了，探索没死）/ grad_norm 0.011–0.06 /
长度 508–738 无增长 / **cap 随 reward 同向下降**（step 1–25 → 101–125：
reward 0.718→0.763 同时 cap/条 0.305→0.223、截断 0.107→0.048）。

⚠️ **cap-vs-reward 在控制台看不到**（verl 的 `compute_data_metrics` 只认两个字段），
中途要监控就按步段聚合 `rollout_dumps/*.jsonl` 里的 32 个 `cap/*` 字段。

## 4 · ★★★ 分卡是异步的硬前提（🔴 **限制已解除，方法论仍然有效**）

verl 的两条异步路径都要求 **rollout 和 training 在不同的 GPU 上**：

- `one_step_off_policy/ray_trainer.py:89` — `assert not self.hybrid_engine`（显式禁止 colocate）
- `fully_async_policy` — `trainer_pool` 和 `config.rollout.n_gpus_per_node` 是两个独立资源池

**写这节的时候本机只有一张 5090，所以「吞吐收益」和「分布漂移」量不了。**
现在是 **4×5090**，两条路径都已实跑打通（`one_step_off` / `fully_async`，
见 `05-handoff.md` §2.2）⇒ **这条限制不再成立。**

⚠️ **但真异步跑通并没有让 §4.1 作废，反而给了它一个实证**：M7 那一跑
`partial_ratio = 0`、分布漂移 `total_variation = 0` —— **不是没测到漂移，是那一跑里
没有漂移可测**（轨迹 ~700 token 相对同步周期 4 步 ≈ 300 s，根本碰不到版本边界）。
⇒ **真异步能不能量到 σ²(k)，取决于调度恰好产生多大的 k**，而离线合成里 k 是我们给的。

### 4.1 离线合成：k 精确可控，与真异步互补（不是替代）

研究假设的核心量是

$$\mathrm{ESS}/N \approx \exp(-T\,\sigma^2(k))$$

要量 $\sigma^2(k)$，**并不需要真的异步**——异步只是产生 staleness 的一种方式。
直接做法：把第 $t-k$ 步 policy 生成的轨迹留着，用第 $t$ 步的 policy 重算 logprob，
得到 ratio 分布 → ESS。$k$ 由我们精确控制，而不是由调度随机决定。

| | 真异步 | 离线合成 |
|---|---|---|
| $k$ 的取值 | 随机、由调度决定（**M7 实测 k 根本没长出来**） | **精确可控**，能扫 k=0,1,2,4,8 |
| 硬件 | ≥2 GPU（✅ 本机 4 张，已打通） | 单卡即可 |
| 能测 σ²(k) 曲线 | 能，但含混杂**且要碰运气** | **能，且干净** |
| 能测吞吐/空转 | ✅ | ❌ |
| 能测分布漂移 | ✅ | ❌ |

⇒ **两边都要**：H1/H2 的核心曲线用离线合成扫（干净、可控、便宜），
   吞吐与漂移用真异步补 —— 但**真异步要先让轨迹真的跨越版本边界**
   （调大 `--latency-scale` 或缩短同步周期），否则量到的只会是又一个 0。

我们已经有 σ²(k=0) 的第一个实测点：ESS/N = 0.846，T ≈ 825 token
⇒ $\sigma^2(0) \approx 2.0\times10^{-4}$/token。

## 附录 A · v8 基线的预期（写于 2026-08-11，跑之前）

沙盒大改之后，旧的 base 数据（0.502 / EVAL 64 条）**全部作废**：
预算单位从元变成分、写动作必须带幂等键、工具从 22 个变 24 个、
prompt 渲染顺序变了、多了十类失败注入。EVAL 从 64 涨到 104 条。

| # | 预测 | 判据 |
|---|---|---|
| P1 | 总体 **0.25–0.40**，明显低于旧的 0.502 | 平均 reward |
| P2 | **F 类 < 0.20**，明显低于非 F 类 | 按 case_id 前缀分组 |
| P3 | **写动作大面积失败** —— base 不知道要传 `client_request_id` | tool_errors 暴涨 |
| P4 | **单位错**：用户说「840 元」，base 大概率填 840 而不是 84000 | policy 子分塌陷 |
| P5 | **全灭格子大幅增加**，集中在 `FAIL_*` | 零梯度构成 |
| P6 | 注入类有非零的 `prompt_injection_cap` 命中（封顶 0.0） | cap 分解 |

★ **P3 是最需要注意的一条**：base 会因为一个纯格式问题（漏一个参数）
在**所有写动作**上失败。这不是能力问题，是「约定未知」——
按 M0 的分类它属于**廉价死格**，SFT 一个 epoch 就能解决。

⚠️ 读结果时必须把这一层剥掉再看，否则会把「不知道要填这个字段」
误读成「不会做这个任务」，进而把 SFT 桶选错。
这正是 M0 那条教训的复现场景：**`p=0` 有两种成因，混在一起会把 SFT 引向错误方向。**

### 不测旧 SFT 的理由

`checkpoints/sft/v3_ctrl` 是在**另一个世界**里训的（22 工具 / 元 / 无幂等键 /
无失败注入 / 不同的 prompt 渲染）。拿它测 v8，分数低是因为世界变了，
不是因为模型不行 —— 数字没有意义，40 分钟 GPU 白花。

正确顺序：**测 base → 按新审计重切 SFT 桶 → 在 v8 上重训 → 再评**。
