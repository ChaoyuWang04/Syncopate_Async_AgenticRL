## 5 · ★★ 守则（都是拿代价换来的，不是风格偏好）

**① 判据要写在「两个东西应当相同」的地方，不要写在「这个数应该在某范围里」。**
前者非黑即白、不需要阈值、不会因基线漂移失效。
2026-08-18 抓到那六个问题的**全是前者**；而 `ESS<0.3` 正是后者的典型 ——
它写满了、真的在跑、也真的报了个数，**只是量的不是我们以为的那件事**。

**② 凡是"我假设 X 成立"的地方，写成断言。成本几乎为零。**
E21 就是被一句顺手写的「DDP 下各 rank 的 LoRA 应该相同」炸出来的。
⚠️ 而且**保护性逻辑必须提成一份函数、所有路径共用**（`syncopate/train/ckpt_guards.py`）——
当时另外两个读 ckpt 的脚本**没有这句话**。

**③ 判据太宽会制造假警报，而假警报会训练人忽略这条判据 —— 比没有判据更糟。**
今天连续三轮误伤（`18.8%` 在 infra 那边指的是**时间**测量、`EVAL 254` 是 v12 的真实数字…）。
⇒ 加任何"黑名单型"判据之前，先 `grep -rl` 确认它**只命中你想要的那处**。

**④ 匹配不上时，宁可报"没有"，也不要猜。**
选点工具用文件名模糊匹配，撞到 **v3 时代**的审计，打出一组
「看起来完全合理、其实是另一个模型」的数字。

**⑤ 先量再罚 / 先测量后动手。** 今天在 P0-2、P0-3 上反复吃亏：
两次都是"看起来该加大惩罚"，查下来都是我们自己的标定错了。
⚠️ 尤其：**验之前别加大护栏惩罚**，否则会把错误的行为训进权重。

**⑥ 位移是输入，不是产出。** AdamW 下 `位移 ≈ lr × 更新次数`，与梯度好坏无关
⇒ 拉 lr / 加次数**必然**得到更大位移，那是算术不是证据。
**判据必须是任务级尺子**（冻结 EVAL 配对 + 看「显著变好/变差/没动」三个计数，
不看均值 —— 均值是相抵之后的残差）。

**⑦ 别把"施工完成"读成"验收通过"。** 这份文档以前就是这么写的，
于是「M7 已验收」被下游引用了两天。**空着的门槛应读作"无法判定"。**

**⑧ 提交按路径 `git add <具体文件>`，别用 `-a`** —— 两条线共用一个仓库。

**⑨ 跑训练只走固定管线，契约参数一个都不许在脚本里传。**（2026-08-19 立，判据见 `08 §4.0`）
入口只有 `syncopate.train.sft` 和 `syncopate.train.launch_rl`；
长度预算与采样参数的唯一来源是 `rollout_budget.py`，**不传就是对的**。
⚠️ 判据是「**一律不许传**」而不是「传的值要对」—— 因为 2026-08-18 那 11 个脚本
**传的值当时是对的**，正是它们成了下一次漂移的来源。
**问题不是值错，是存在一份副本。**
⇒ 一般化：**凡是"这个值应该和那边一致"的地方，正确的判据是"这里根本不该有这个值"。**

**⑩ 该停的时候由判据说了算，不由步数说了算。**（2026-08-19 立，判据见 `06 §2.0`）
RL 跑到步数就停 = **在还有东西可学的时候停下**。
`[实测]` 60 步时零梯度率仍在创新高（15%→52%）、RL 桶只覆盖 22.7%。
⇒ 上线候选必须跑到「零梯度率连续 3 个窗口没有创新高」；400 步是**下限不是目标**。
⚠️ 而**约束加在"晋级"上不加在"起跑"上** —— infra 的短实验一点不该被挡。
⇒ 一般化：**要挡的是"把没做完的东西当成做完的"，不是"不许做短的"。**

**⑪ 更新文档的默认动作是「改写」，不是「追加」。**（Chaoyu 2026-08-19 立）
前科：本文曾膨胀到 916 行、`01` 到 1269 行、主线全套到 19 份 8334 行 ——
同一天两道压缩令。膨胀不是无害的：**第一天要读的东西被历史淹没 = 导航失效**。

"读完没问题"恰恰是最危险的信号 —— 文档写的是作者以为该写的，盖不住你误解的那部分。
（当天实例：08-29 交接，前任一句回信就补了三条文档外的现场细节——decider 顶名、
盲评对端文件、门槛⑦读数位置。）前任会话已下线联系不上 ⇒ 把这轮核对的问题
和自己的答案写进交接快照，显式标注「**未经前任确认**」。

**⑬ 没有细到每一步的计划 + 每步的量化验收，就不许动手。**（Chaoyu 2026-08-29 立，两线通用）
任何实验/施工开工前先写出：**每一步做什么 · 产物落在哪 · 用哪个数字判过没过**
（阈值和读数位置都写死）。判据**跑之前注册**——跑完再定阈值是自证
（范本：`24`/`25` 的逐阶段门槛表，`06 §1` 的起训自查清单）。
⛔ **计划里不许留还没查清楚的部分**：「到时候再看」「先跑起来再说」等于没有计划。
凡是心里还含糊的地方，先查清、或先按⑫问上一任/Chaoyu，**不许带着模糊开工**。
（这条是⑦「施工完成≠验收通过」的上游：⑦ 管跑完怎么判，⑬ 管跑之前就把判法定死。）
**附则·钉死判据前先三查**（2026-09-02 立，代价 = v15 R5 八条尺子病，`26 §2.3`）：每条门槛注册前答三句
**可测**（n/遍 ≥20、SE ≤ 失败余量；差值型 SE_diff ≤ 阈值/2，否则改判读法）· **可达**（当前数据先把这个数算一遍）·

**⑭ 方案定死之后，用 `/goal` 把验收条件钉在会话上，让它自己跑到达标为止。**（2026-08-29 立）
`/goal <条件>` 设一个完成条件并**立刻开跑**；每轮结束由一个小模型判达标没有，
没达标就自动开下一轮，不用人一轮一轮催。`/goal` 看状态 · `/goal clear` 清除 ·
一个会话只有一个目标（新的覆盖旧的）· 条件上限 4000 字符 ·
无人值守要配 auto mode（`/goal` 自己不改权限模式）。

```
什么时候用   ⑬ 过关之后（方案已细到每一步、判据已量化）。
             ⛔ 方案还模糊时不许用 —— 那只是让它**更快地**做错事。
★★ 最重要   评审模型**不跑命令、不读文件**，只看**对话里已经出现的内容**。
             ⇒ 判据必须被**打印出来**，否则它是在给"我声称做完了"打分。
             这正是本项目最贵的失效形状（infra 守则①：判据行没出现 = 那个机制没生效）。
怎么写       ① 一个可测的终态 ② 明说怎么证明（哪条命令、读哪个数）
             ③ 不许动的东西（哪些文件/服务/卡不能碰）④ 轮数上限（"或 N 轮后停下"）
             ⑤ 加一句「不许为了达标而放宽判据」—— 否则它会去改判据而不是改代码
自己会停     达标 / 判定不可能 / 你 clear / 撞上要人修的错（认证·余额·上下文溢出·
             模型不可用 ⇒ 修完 `/goal` 重设）；连续几轮不动工具也会自动把控制权还你
和 /loop 的别 `/goal` 由**条件**驱动（达标即止），`/loop` 由**时间**驱动（到点再跑一遍）。
             要"做到某个状态"用 goal；要"每隔多久看一眼"用 loop。
```

**⑮ 训练样例必须和线上真实遇到的**逐项同形**——不同形的地方就是训练在教错东西。**
（Chaoyu 2026-08-31 立；代价：v15 R5 四条门槛红，失分全在多轮档）

训练数据的目的就是"让模型见到它上线后会见到的东西"。**只要某一项两边长得不一样，
模型学到的就是那一项的错误版本**，而且它**不会报错**——离线评测照样好看，
要到真起服务才显形（这正是「机制在但没接上」第八形态的数据版）。

08-31 通查实测：训练样例与线上有 **7 处**不同形，全是"造数据时的临时办法"，
一处都没被登记成欠账：

```
① 多轮历史的位置   训练=折成文本塞进题面「[上一轮] 用户：…」 / 线上=真消息对
② 上一轮助手内容   训练=占位符「已给出结论」               / 线上=完整原话
                   ⇒ 教模型"历史里助手那句没信息量，不用看"
③ 本次要交哪些字段 训练=每题真实机器字段（decision/approved_budget…）
                   线上=写死一对占位；v15 下被过滤 ⇒ **整节消失**
                   ⇒ 训练时永远有人告诉它"交这几格"，线上一格都不说
④ 当前投放任务     训练=直接给出目标 campaign_id / 线上=只给一串在投清单，要自己挑
⑤ 当前时间格式     训练=ISO 带时区 / 线上=纯日期
⑥ 工具菜单大小     训练=按题裁剪 16–17 个 / 线上=全量 34 个
⑦ 历史里的 think   训练=每轮都有 <think> / 线上=回灌历史不带
```

**根因不是谁疏忽，是管线的形状限制**：`Case` 只有**一个** `user_message` 字段，
整条数据管线结构上只能造单轮题；要多轮就只能往题面里塞文本，要"告诉模型交哪些字段"
就只能用 gold 的 `required_answer_fields`（线上没有 gold，只能写死占位）。
⇒ **一般化：凡是"为了让数据造得出来"而采取的临时形状，都要当场登记成欠账**，
否则它会一路带到上线，而中间每一道离线判据都不会拦它。

```
开工前必做   把"训练样例"和"线上一次真实请求"打印出来**逐项对照**（不是抽查，是逐项）：
             system prompt · 题面各字段 · 历史的位置与形状 · 工具菜单 · 观测渲染 ·
             终答形状 · think 块。任何一项不同 ⇒ 要么改数据、要么改线上，
             **不许留着"反正差不多"**。
判据形状     这条天然是守则① 的「两个东西应当相同」型：不需要阈值，
             直接断言"同一件事在两边渲染出的文本结构一致"。
往哪边对齐   默认**对齐到线上**（线上是契约的定义方，见 `21` 的"沙盒是 runtime 的子集"）。
             反过来让线上迁就训练数据 = 把欠债转移到产品上。
```

**⑱ 训练数据的三桶隔离必须是硬机制，不许靠"写行的人记得过滤"。**（Chaoyu 2026-09-04 立；代价 = v16 run24 产物 1270 行里 367 行底题越桶：
104 条来自冻结 EVAL、263 条来自 RL 桶——专用建库脚本整批读题后各桶手动过滤，多轮/六族两条路径漏了，考卷句级泄漏闸看不见改写过的题面）

① 源头   建库只能拿到 `split.load_split_bundles(batch, split_dir, "sft")`——别的桶的题根本不进内存
② 登记   每行带 `source_case_ids`（派生行由 as_multiturn 登记底题；无底题的行如闲聊/L1 定义为空）

判据形状 守则①「两个东西应当相同」：底题所在桶 == 产物桶，不需要阈值。测试 tests/pipeline/test_split_isolation.py
⚠️ 一般化 任何"绕过正规管线"的专用脚本，出口都必须走正规管线的写盘函数——隔离/体检/同形这些闸长在出口，不长在人的记忆里

**⑯ 装任何框架/库都要核对「是不是最新稳定版」，不是的必须写明原因。**（Chaoyu 2026-09-03 立）
这是学习项目：简历上写的技术栈被辅导老师指出"都是一年前的"，根因是长期为 5090 迁就旧版本（vLLM 0.12、torch 2.9、verl 0.8）。
⇒ 每次配环境：① 先查 PyPI/GitHub 最新稳定版 ② 装的不是最新 ⇒ 在依赖表注释里写"为什么"（谁钉了它）③ 机器判据：
`modal_app/stack_probe.py --steps versions`（装的版本 vs PyPI 最新，不是最新且不在白名单 = 红）。
硬件同理：PRO 6000（sm_120）跑不了 FA4/TMEM ⇒ 一切在 B200（sm_100）上配（26 §6 裁定⑫）。

**⑰ 一切网络重活默认在 Modal 容器里做，本机只做编辑与判读。**（Chaoyu 2026-09-03 立）
本机在大陆，拉 GitHub/HF/PyPI 一定慢：09-03 本机 `uv lock` 拉一个几百 MB 的轮子直接超时，同一件事在 Modal 容器里 2 分钟。
⇒ **默认走 Modal 的四件事**：① 依赖解锁 `modal run modal_app/lock_on_modal.py`（解完把 uv.lock 拉回本机进 git）
② 权重 `stack_probe --steps models`（HF → Volume，字节数对账）③ 代码 git clone 进 Volume（`/vol/repo`，每次起跑 reset 到 origin/main）
④ 大文件/编译产物一律落 Volume（`/vol/models` `/vol/flashinfer_cache` `/vol/vllm_cache` `/vol/_audit`），本机只留 json 读数。
本机只做三件：改代码 · 提交 · 读 `_audit/` 里的判据。

**★ Modal 独有的红利：A/B 各臂并发跑（Chaoyu 2026-09-03 点出）。** 每个 `modal run --detach` 是一个独立容器/独立 GPU，
多臂对照不必排队——单变量对照的 N 个臂同时起，墙钟 = 最慢的那一臂而不是求和。用法与纪律：
```
怎么起     每臂一条 `modal run --detach … --steps X --arm <名字>`，产物落 Volume 下**各臂自己的目录**（`/vol/_audit/<exp>/<arm>/`）
镜像       同一份镜像哈希 Modal 只建一次，多臂共用；改了依赖表的臂会各建各的，先建好再起臂
⛔ 一个写者 两个臂不许同时写同一路径：`/vol/repo` 的 git reset、同一 parquet、同一缓存目录 —— 09-03 差点让 v16 重建被另一臂 reset 掉。
           共享只读（模型权重、缓存）没问题；要写就各臂各目录
拓扑指纹   各臂可能落在不同宿主机/区域 ⇒ 每臂读数带 topology 指纹，跨臂比较先看指纹是否同型（速度类读数尤其）
成本       并发不省钱：臂数 × 单臂时长 × 单价；省的是等待时间。GPU 并发上限 Starter 10、Team 50
汇总       各臂 json 落盘后本机一条命令汇总成表（同尺子、同噪声地板），不许各臂各自下结论
```

**和 Modal 打交道的坑（每次撞到就加一行；细节与命令在 `modal_app/README.md §运维坑`，这里只留判据）**
```
停 app 必带 --yes     非交互终端 `modal app stop` 静默不执行 ⇒ 停完 `modal app list` 必须看到它消失（09-03 白烧 B200 40 min）
删 Volume 要 --yes     `modal volume delete <名> --yes`；⚠️ 删文件的 `modal volume rm <名> <路径>` **不吃 --yes**（09-04 实测报 No such option，命令静默没删 ⇒ 删完 `modal volume ls` 核对）
GPU 函数可抢占且不可关 每步幂等、结果落 Volume、长任务 --detach；不要在一个函数里串太多步
镜像层顺序           三件套（pyproject/uv.lock/uv.toml）在前、代码不进镜像 ⇒ 改代码不重建镜像；改依赖才重建
AOT 优先于 JIT       FlashInfer/FA 这类库能装预编译就装（flashinfer-jit-cache/cubin、mjun0812 flash-attn 轮子）；

拓扑不承诺           同一 :2 保证同机，但机器/区域/云每次可能不同 ⇒ 读数带拓扑指纹，跨次不直接比
解析结果走文件       子进程 stdout 尾部会混进 stderr 警告 ⇒ 结果写 json 文件再读，别取"最后一行"
判据随卡变           capability 期望值、显存阈值都是卡的属性，换卡先改判据
⛔ 对象不许条件定义   `modal.Secret/Volume/Image` 不许放在按环境变量分支的语句里：本机与容器求值不同 ⇒
                     "Function has 3 dependencies but container got 2"，函数在 hydrate 阶段直接死（09-03 run13）。
                     要"可选"就先建占位 secret（`modal secret create wandb WANDB_DISABLED=true`），代码里无条件引用
Volume 路径分层       /vol/repo.git（bare 镜像，flock）· /tmp/repo（每容器 checkout）· /vol/data/{batches,sft,rl}（gitignored 数据）·
                     data/splits 在 git 里不软链 · /vol/models · /vol/_audit/<exp>；`modal volume cp` 对不存在的父目录会失败，用容器内 shutil
新栈 API 变化         transformers 5：`apply_chat_template(tokenize=True)` 返回 BatchEncoding ⇒ 只走 `rollout_loop.chat_template_ids`
推代码走 SSH          本机 HTTPS `git push` 会静默挂死（09-04 实测 15 min 无进展、与凭据无关）⇒

⛔ pkill 别按命令行匹配 `pkill -f "git push"` 会把**自己这条 shell**一起杀（命令行里含同一串）⇒ 用 pgrep 看 pid 再 kill
