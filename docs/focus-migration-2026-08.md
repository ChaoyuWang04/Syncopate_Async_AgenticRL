## 0 · 三十秒读懂

2026-08-17 换了一台机器。它触发了两件不同性质的事：

1. **基线作废** —— 一批以「卡间 6.4 GB/s」为分母的数字失效了，必须重测；
2. **焦点迁移** —— 更要紧的是，Track A 的论证重心从「**拓扑有多恶劣**」
   挪到了「**负载有多稀疏**」。这不是被迫的退让，**是一次升级**。

---

## 1 · 硬件换代：哪些前提变了

| | 迁移前 | 迁移后（当前） |
|---|---|---|
| 拓扑 | 四卡对称、单 NUMA（PHB） | 2 socket，**2+2**：GPU0/1 与 GPU2/3 各挂一个 NUMA，跨组走 UPI |
| PCIe | max Gen4 | **Gen5 x16** |
| all-reduce busbw @256MB | **6.44 GB/s** | 组内 **28.8** · 跨 socket **22.2** · 四卡 **25.6** |
| `/workspace` | 网络盘（mfs），有 `df` 看不见的卷配额、不支持权限位 | 本地 XFS 300 G，权限位生效、无隐形配额 |
| `/` | 不是瓶颈 | 只有 16 G overlay |

**没变的**：仍是 4×RTX 5090 / sm_120；**PCIe P2P 仍然全关**（GeForce 从 4090 起被驱动
关掉，所有 4×5090 都这样），卡间一律经主机内存中转（NCCL 走 `SHM/direct/direct`）。

⇒ 跨 socket 只掉 22%，NUMA 绑定救不回来（22.23→22.34，噪声内）—— 那是 UPI 跳的物理代价。
换算到负载：DDP 梯度 260 MB 从 40.4 ms 变 10.2 ms，**跨 socket 的净代价 1.2 ms/步，
占一步的 0.004%** ⇒ 拓扑本身不构成换机器的理由。

⚠️ **换机器救不回基线** —— 旧机器已不存在，任何新机器都不是它。所以唯一的出路是重测。

## 2 · 逐条体检：哪些结论活下来了

判据只有一个：**这个结论的前提是不是「6.4 GB/s」。**

| 结论 | 前提是带宽吗 | 迁移后 |
|---|---|---|
| **监督密度 4.17%**（E11） | ❌ | ✅ 毫发无伤。它是 agentic 负载的**结构性特征**（prompt 88.3% / 工具返回 7.6% / 助手 4.2%） |
| **sm_120 能力探底**（E16） | ❌ | ✅ 毫发无伤。纯 kernel/ISA |
| **整机占空比 31%**（E08） | ❌ 主要不是 | ✅ 基本完好。四个成因里三次前向（占步 72%，纯计算）、陈旧度节流、配比都与带宽无关 |
| **权重同步 99.94% 不在传输**（E12） | ❌ | ✅ **结论更强**：传输 0.8 s → 0.2 s，固定开销 55.0 s 不变 ⇒ 99.98% |
| **proximal anchor CPU 快照**（E13） | 🟡 走 PCIe 主机侧 | 🟡 方向不变、**量级减半**（Gen4→Gen5） |
| **MoE 三摆法**（E07） | 🟡 表面是 | ✅ 核心论点完好，**但说法要重写**（§3） |
| **FSDP 慢 6 倍**（E02） | ✅ **完全是** | 🔴 **要塌**（§4） |

## 3 · ★ 焦点迁移的实质：从「链路慢」到「数据量比值」

E07 三摆法原来的论证是「**在无 P2P、卡间 6.4 GB/s 的机器上**，分片的 all-gather 代价远超复制」。
带宽 ×4 之后重算，发现它塌不了：

```
配置 A · FSDP 分片    每 micro-batch all-gather   61.1 GB
配置 C · 4bit 复制    每步只同步 LoRA              0.13 GB
                                      比值 = 470×      ← 这是**数据量**之比
```

**470× 是数据量的比值，与带宽无关。** 带宽再快 4 倍，A 仍要搬 470 倍的东西
（绝对疼痛从 9.5 s 降到 2.4 s / micro-batch，而 C 是 5 ms）。

⇒ 论证从「**这台机器链路慢**」改写成「**这个负载的数据量比值是 470×，多快的链路都填不平**」。

★ **这是升级不是退让**：原来的说法绑死在一台机器上，换机器就失效；
新说法是**硬件无关的结构性论证**，和「监督密度 4%」同一个品级。
面试官问「换台好机器你这套还成立吗」，现在有答案。

⇒ **Track A 的重心因此从「拓扑有多恶劣」挪到「负载有多稀疏」**：
监督密度 4%、专家激活 10% —— 这两个是这个项目独有的、硬件换代也带不走的东西。

## 4 · 唯一真正塌掉的：E02

「FSDP 慢 6 倍」的因果链就是「每层 all-gather 8 GB，而卡间只有 6.4 GB/s」。

粗估：首步 1182 s（3 卡 FULL_SHARD）里超出单卡 198 s 的那 984 s 主要是通信，
带宽 ×4 后 ≈ 246 s ⇒ 总计约 444 s ⇒ **「6 倍」大概率变成「~2 倍」**。

**方向不变（DDP 仍然赢），但招牌数字塌 3 倍。** 而这条恰好是 Track A
「拓扑决定该做什么」的核心证据。

⚠️ **上面这段是推算不是实测**（假设「超出部分全是通信」）。
按 `infra_exp/README.md` §4 的纪律，它已作为**预测**写进 `E02-data-parallel.md` §1，
由 **A6** 去证伪。

## 5 · 新机器打开的两扇门

**① `E04 TP/PP` 的停放理由过期了。**
它当初的停放理由白纸黑字是「**6.4 GB/s 上 TP 大概率净负**」。
现在**组内 28.8 GB/s**，TP=2 **限制在同一 socket 内**是完全不同的命题。
按「作废不删、条件满足就复活」的规矩，它已复活为一个 30 分钟探针。

**② 2+2 拓扑本身成了研究对象 —— 迁移前不存在的问题。**

```
迁移前  四卡完全对称     ⇒ 「放哪张卡」根本不是问题
现在    组内 28.8 / 跨 22.2  ⇒ 放置第一次有了意义
```

而且默认配置正好踩在坏的一侧：trainer = GPU0/1/2 中 GPU0/1@node0、GPU2@node1
⇒ **DDP 的 all-reduce 每步都跨 UPI**。候选摆法：

```
当前     trainer 0,1,2（跨 socket）+ rollout 3
候选 a   trainer 0,1（同 socket）+ rollout 2,3（同 socket）  ← 两侧都不跨
候选 b   trainer 2,3 + rollout 0,1                          ← 对称性检验
```

⇒ 已并入 **B11**，把它从「配比调参」升级成「**拓扑感知的放置**」——
一个只有这台机器才提得出的问题。

## 6 · 迁移带来的优先级变化

**价值上升**（都与带宽无关，相对更突出）

1. **B12 / E17 · 训练侧三次前向占 72%** —— 占空比里最大的一块，纯计算。
   带宽变快后它在总账里的占比只会更大 ⇒ Track B 现在最该打的靶子。
2. **A3 / E16 · sm_120 能力探底** —— 不依赖任何被推翻的因果链。
3. **B1 / E12 · 权重同步优化** —— 结论被强化，目标未变。

**必须先做的短探测**（合计约 2.5 h，挡住后面所有对照）

- **A6 · E02 重测**（~1 h）—— 决定「拓扑」这条论证还剩多少力气
- **A7 · 满载降频曲线**（~1 h）—— 它会污染所有多卡对照
- **E04 复活探针**（~30 min）—— TP=2 同 socket 净正还是净负

**要改写而不是重测** —— E07 的论证换成「470× 数据量比值」，A1/A2 照做不误。

## 7 · 这次迁移本身是一份资产

> **「同一套诊断方法搬到新一代硬件上，哪些结论活下来了、哪些被推翻了。」**

这比单独一次测量强 —— 它证明的是方法论，不是运气。
加上此前两次「我证明了自己原来是错的」（ostinato §4.0 因果链被实测推翻、
E11 调研后主动降级不写 kernel），**三次自我推翻**是很难伪造的可信度。
⇒ 简历成果栏写不进去，但**要在面试里主动讲**，别等被问。

## 8 · 同日修掉的三个环境级缺陷（与焦点无关，但同属这次迁移）

都不报错、都会让训练白跑，细节见 `syncopate/05-handoff.md`：

1. **flash-attn 轮子的反向是坏的** —— 前向三项数值全过、反向 nan 或**恒为 0**
   ⇒ verl 跳过 `optimizer.step()` ⇒ RL 完全空转。
   ★ 教训：**「import 成功 ≠ 契约满足」的下一层是「前向对 ≠ 反向对」。**
2. **分卡模式下 3 个 trainer rank 全挤在 GPU0** —— 根因是进程启动钩子在 Ray 设
   `CUDA_VISIBLE_DEVICES` 之前 import 了 verl，把 CUDA 设备枚举固化了。
   ★ 新纪律：**进程启动钩子里只许做纯 Python 的事。**
3. **`--weight-sync-bucket-mb` 在 colocate 下被静默忽略**。

★ 还有一整类「**只有干净机器才暴露**」的缺口（依赖表缺项、派生数据没进搭环境步骤、
`uv sync` 静默卸载手动装的包）—— 记在 `.claude/memory/clean-machine-only-gaps.md`。
⇒ **干净机器重建本身就是一次审计**，比任何 review 都有效。
