**模型不是在"自由表达"，是在填我们规定的那张表。** 表格长什么样，行为就长什么样 ——
所以「模型不会说人话」这类判断，**先看我们让它填的是什么表**，再谈训练。

## 2026-08-20 的实证（runtime 真跑）

真人试用观感：终答全是 `no_change` / `roas_drop` / `executed_but_no_policy`
这种**机器标签**，不像跟人说话。

根因一半在 `answer_fields`（渲染进 prompt 的"本次结论需要给出的字段"）：
runtime 只给了一个格子 —— `summary`「本次任务的结论」。
⇒ 它往里填工单式的短标签。**不是不会说，是没给它说话的地方。**

⚠️ 另一半是训练目标本身：SFT gold 的 `answer` 就是给评分器**逐字段匹配**用的
（`{"decision":"scale_down","factor":0.8}`）⇒ **"说清楚"从来不在目标函数里**。
⇒ 短标签**不是退化，是学到位了**。要改得动数据契约（v14），不是只改 prompt。

## 三个变体的实测（`scripts/probe_answer_fields.py`）

| 表格 | 闲聊·自然语言 token | 任务·首步调工具 |
|---|---|---|
| A 只要 `summary`「本次任务的结论」 | 2（机器标签） | 2/2 ✅ |
| **B 只要 `reply`「用人话说清楚」** | **21（真人话）** | **1/2** 🔴 |
| **C `summary` + `reply` 并列**（采纳） | 10 | 2/2 ✅ |

## ★★★ B 那一行是这条记忆的核心

B 档下问「查一下 CMP_1 昨天的花费」，它**不调工具了，直接编出
"今日投放未启动，数据不可用"**。

⇒ **表格暗示了它的工作是什么。** 表上只写"请用人话说清楚"，它就以为活是**写字**，
忘了活其实是**先查、再说**。
⇒ 一般化：**只优化表达，会把办事能力换走。** 这条此前只是设计文档里的"担心"，
现在是十分钟买到的实测证据（`docs/syncopate/22 §J-6`）。

## 怎么用

```
"模型不会 X" 的排查顺序
  ① 我们让它填的表里，有没有 X 的位置？        ← 最便宜，先查
  ② 训练目标里，X 被打过分吗？                 ← 没有的话，它没理由学
  ③ 才轮到"能力退化了，要训练"                 ← 最贵、不可逆、难归因
```

⚠️ 改契约是**可撤的配置**，训练是**改大脑**：不可逆、难归因、可能一边教会说话
一边把办事本事弄坏（B 变体就是这个风险的预演）。⇒ 能用①解决的，别上③。

⚠️ 但契约变更**会传导到数据**：v14 的 gold 要按新契约重造，且 reward
**不许按字面匹配 `reply`** —— 那会把"说人话"变成"背模板"。
