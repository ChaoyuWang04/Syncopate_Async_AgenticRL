**"多样性塌在某一个通道里"是本项目数据侧最贵的失效形状。判据必须逐通道量，且要
归一化（抹掉数字/ID）之后再比 —— 逐字比很容易被躲过，句式比躲不过。**

Chaoyu 2026-08-30 的原话：「我们不能每次都花了超级长的时间走完完整的训练之后再来
返工来做检查。」此前**三次**都是训完、评完、跑完考场才发现：

```
㉖ 41.8% 的行以同一句「已经按上面的结果处理完了。」收尾（v13 压舱 gold 没有 reply）
㉚ ㉖ 的修法（字段渲染成中文句）把常量换成了**模板**：rag_policy 30.3% 同句式、
   cot_hard 100%（㉖ 只修了压舱桶漏了 CoT 桶）、32 个答案各自服务 ≥3 个不同题面
㉗ 150 行把人话塞进 session.report 再原样抄一遍 ⇒ 模型学成"复制"，复制一断就吐背下来的 reject
```

三次的共同点：**当时的闸只量了另一个通道**（密度闸只量终答尾巴，量不到 report 参数
和信令 explanation），而且每一条数据都合法、不报错。

**Why：** 训练数据的"病"不会让任何东西崩掉 —— 它只是让模型学到一个更省事的策略
（背一句话 / 复制 / 念表）。这种策略在离线评测里往往还能拿分，要到真跑服务才显形。

**How to apply：**
1. **开训之前**跑 `scripts/v16_data_audit.py`（已接进建库的最后一道闸，不绿不出 parquet）。
   通道清单 = 模型实际会读到/被监督到的每一段：终答 · 题面 · think · 工具调用参数 ·
   信令自由文本 · 收尾。**不挑通道**。
2. **归一化后再比**：`\d+`→§N、`CMP_xxx`→§ID。㉖ 那 41.8% 按句式量第一眼就看得见。
3. **"一个答案服务了几个不同题面"** 是"预设答案"最直接的形状；但要按**问的是什么**
   归一（「什么是毛利？」「那毛利呢」是同一个问题，否则会把正确行为报成病）。
4. 闸要跑**落盘后的真产物**，不能跑内存中间态 —— ㉖ 那次闸写在生产者里，缓存命中就被绕过。
5. 新判据先在**已知有病的旧数据**上验一遍：照得出已知的病，才敢拿它当闸。
6. 生成教师物料时，除了角度多样性还要单独管**收尾**（同一个末 10 字全库 ≤4 次）——
   ANGLES 管切入角度，管不到口头禅。
