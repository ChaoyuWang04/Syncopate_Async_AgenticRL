**训练数据的目的就是「让模型见到它上线后会见到的东西」。只要某一项两边长得不一样，
模型学到的就是那一项的错误版本——而且它不会报错，离线评测照样好看。**

Chaoyu 2026-08-31 立为核心守则⑮（`docs/syncopate/00-START.md §5`）。原话：
「训练侧所用的数据应该和实际案例中遇到的一样，这才是训练的目的。」

**代价**：v15 R5 四条门槛红（L1-iv 65.8/需 90 · L2 53.0/需 70 · 难例思考率 0/需 50 ·
reject 表达率 12.5/需 90），**失分全在多轮档，单轮档（343 条冻结 EVAL）是好的**。

08-31 通查查出 **7 处**不同形，全是造数据时的临时办法，一处都没登记成欠账：
① 多轮历史位置（训练=折进题面文本「[上一轮] …」/ 线上=真消息对）
② 上一轮助手内容（训练=占位符「已给出结论」/ 线上=完整原话）⇒ 教它"历史不用看"
③ 本次要交哪些字段（训练=每题真实机器字段 / 线上整节消失）⇒ 解释了"查了不读数"
④ 当前投放任务（训练=直接给目标 campaign / 线上=一串清单要自己挑）
⑤ 时间格式 ⑥ 菜单大小（16 vs 34）⑦ 历史里的 think 块

**Why：** 根因不是疏忽，是**管线的形状限制**——`Case` 只有一个 `user_message`，
结构上只能造单轮题；要多轮只能往题面塞文本，要"告诉模型交哪些字段"只能用 gold 的
`required_answer_fields`（线上没 gold ⇒ 写死占位）。临时办法没被登记，一路带到上线。

**How to apply：**
1. 开工前把「一条训练样例」和「一次真实线上请求」**打印出来逐项对照**（逐项，不是抽查）：
   system prompt · 题面各字段 · 历史的位置与形状 · 工具菜单 · 观测渲染 · 终答 · think 块。
2. 这条是守则①「两个东西应当相同」型判据：不需要阈值，直接断言两边渲染结构一致。
3. **默认对齐到线上**（线上定义契约，见 [[sandbox-is-subset-of-runtime]]）；
   让线上迁就训练数据 = 把欠债转移到产品上。
4. 凡是"为了让数据造得出来"而采取的临时形状，**当场登记成欠账** ——
   中间每一道离线判据都不会拦它。
