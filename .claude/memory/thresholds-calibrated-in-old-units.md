**换契约（或任何换单位的改动）会让「按旧口径标定的数字」**同时**失效，而且一条都不会自己报错。**

2026-08-30 v15 施工一天内撞了**五次**，五次形状完全一样：

```
① ⑤⒝ think 判据「全库 20–35%」   v15 每轮都有 think 块 ⇒ 分母从"几十行"变成"3334 轮"
② CoT 行数下限 40                v15 每行带 4–6 段教师推理，行重 3–5 倍 ⇒ 与 token 带宽不可兼
③ 跨代桥测（R3②）               v14 输出在 v15 解析器下 104/104 判 shell_residue ⇒ 全趴 0
④ prompt 上限 5120               判据当时量的是 R0 的**单轮**数据，真正要训的是 R2 的**多轮**数据
⑤ 份额带宽 L2 [10%,17%]          v13 压舱石桶轨迹最长、涨得最多，把 L2 从带内挤到 8.3%
```

**Why：** 这些数字都不是错的——它们在**标定它们的那个世界里**是对的。换契约改的是"单位"
（每行多少 token、每轮有没有 think 块、终答长什么样），而阈值是按旧单位写死的常数。
⇒ 判据不会红（它照常跑、照常报数），只是**量的是另一件事**。

**How to apply（写门槛时的三个默认动作）：**
1. **问"这个数是按什么单位标的"** —— 行数？token？占比？分母是谁？换契约会不会动那个单位？
2. **判据要挂在「真正会被用的那份数据」上**，不是挂在当初量过的那份上。
   （④ 的根因；同族还有 R2 那次「缓存把坏结果固化，判据一命中就被绕过」）
3. **跨版本判据先问「新口径在旧产物里存不存在」** —— 不存在就是注定红/注定无法判定的判据
   （③ 与 R1② 都是这条，同一天犯两次）。

**处置纪律（Chaoyu 08-30 三次裁定确立）：**
- 三条判据互相打不开时，先**穷举可行边界**再报，不要自己挑一条放宽（CoT 那次实测上界=19）
- 改判据前先问：这三条里**哪一条是"拍的"**、哪些各有来源（梯度预算 / N3 按需思考 / 服务上限）
- 抬阈值要抬到**真实约束**上：prompt 上限的真实约束是服务侧 14336，不是 5120
