**约束加在「晋级」上，不加在「起跑」上。**

## 起因（2026-08-19）

要立一条纪律：**上线候选必须跑到没东西可学为止**（不是跑到步数就停）。

直觉做法是在 `launch_rl` 起跑处强制最少步数。⚠️ **那会当场挡住 infra** —— 他们一直在用 RL 跑 60 步的精度/吞吐实验，而他们**本来就不需要**跑到没梯度。

⇒ 改成：

```
--purpose probe       默认。实验 —— **不受任何约束**
--purpose candidate   上线候选 —— 受最少步数 + 完成判据约束
```

**任何跑都随便跑；只有「声称自己是上线候选」的跑才过闸**（`syncopate/train/candidate_gate.py`）。

## ★ 那"主线忘了声明"怎么办 —— **不靠记性**

忘了声明的后果是**晋级时被拦下**（`run_purpose.json` 里写着 probe），
**不是**"悄悄拿一个 60 步的短跑当候选"。

⇒ 这是这条模式的关键：**遗漏的失败方向是"被拦下"，不是"混过去"。**

## 一般化

> **要挡的是「把没做完的东西当成做完的」，不是「不许做短的」。**

同族的判断在这个项目里出现过好几次：
- `contract` 组的逃生口 `# CONTRACT-OVERRIDE: <理由>` —— 不禁止覆盖，但要**留痕**
- `tool_parity` 的账本 —— 缺口**不判红**，但**必须写下来才算被承认**
- 灰测闸门 —— 不限制流量比例，限制 `automation_tier`（**能自己做多少**）

⇒ 共同点：**判据管的是"有没有如实声明"，不是"能不能做"。** 这样它既有约束力，又不会变成另一条线的路障 —— 而路障会被绕过，绕过之后判据就名存实亡了。
