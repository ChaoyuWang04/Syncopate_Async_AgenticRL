**登记 ≠ 实现。** 一张登记表填满了，不代表被登记的东西存在。

## 实测（2026-08-19）

`syncopate/runtime/tools.py` 的 `WRITE_TOOLS` 登记了 **8 个写工具**的权限与幂等键。
我据此向 Chaoyu 报告「runtime 实现了 8 个工具」。

**建了对齐账本（`tool_parity.py`）之后才发现：真正有实现的只有 2 个。**
那 8 个里 **7 个根本没有实现** —— 登记表填了，实现没有。

⇒ 而这个缺口**存在了很久，没有任何东西在喊**：
「没实现」不报错，它只是让某个工具**在 runtime 里不存在、在训练里存在**。

## 为什么它骗得过 code review

登记表是**最像"证据"的东西** —— 它具体、完整、有结构。
读到 `WRITE_TOOLS` 有 8 条，最自然的推论就是"支持 8 个写工具"。
⇒ **而那正是 [[project-mechanism-not-wired]] 的一个新形态：机制的"名册"在，机制本身不在。**

## 怎么防

判据形状是「**某集合应当完整**」（非黑即白，不需要阈值）：

```
已实现 ∪ 已登记缺口  ==  真相来源的全集
已实现 ∩ 已登记缺口  ==  空
```

⇒ 关键是**真相来源只有一个**（这里是沙盒的 `REGISTRY`），账本不另抄一份名单。
⇒ 而且要有一条判据检查「已实现」那一半**真的有实现**（签名对得上），
   不能只比名字 —— 否则账本本身又变成一张新的登记表。

⚠️ 顺带：缺口**每条要写清楚在等什么**。只写名字会变成一张永远不会被清空的名单
（这条判据当场判红了我写的 13 条「B-2：写工具」）。
