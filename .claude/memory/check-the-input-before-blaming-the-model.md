**任何"模型行为变差"的归因，第一步先查输入有没有被截断。** `clip_ratio` 一个数就能挡住一整条错误的归因链。

## 它花了多少钱

2026-08-19 之前，我基于三个跑做了一整套分析，结论是「**当前 reward 会系统性地把"不拒绝"训进权重**」——还算出了牺牲收益比、盈亏平衡点、四类风险排序，把它排成了阻塞所有 RL 重跑的**队首任务**。

**全部作废。** 那三个跑的 prompt 是 **100% 被截断**的：

```
             clip_ratio   prompt_mean
r1_tokenis      1.0          3584.0    ← 被顶死在上限
r1_seqis        1.0          3584.0
e17a（5120）    0.0          4187.9    ← 真实长度
```

★ `prompt_mean` **恰好等于上限**，那不是"平均长度"，是**每一条都被砍到上限**。真实均值 4188 ⇒ 每条平均砍掉 600 token，而且是**左截断**，砍的正是 system prompt 的规则区（「每步只输出一个 tool call」「调查先于任何结论」，存活 0/659）。

prompt 完整之后，那些"症状"**全部反号**：该 defer 97%→**100%**、REJ **+0.203**、`fabricated_safety_line_cap` **−2**、任务分 **+0.137(t=11.6)**。

## 为什么它特别难防

**被截断的模型看起来不像"环境坏了"，看起来像"模型学坏了"** —— 它照常输出、照常调工具，只是不遵守那些被砍掉的规则。于是每一个下游指标都指向"reward 有问题"，而且**彼此自洽**（defer 掉、REJ 掉、编安全线涨，连成一条完美的图景）。

⇒ 同 [[silent-degradation-weight-sync]] 那条：**一个环境缺陷会制造一整套自洽的错误解释。**

## 怎么做

```
归因"模型变差"之前，按这个顺序查：
  ① prompt_length/clip_ratio      不是 0 ⇒ 先停，别往下归因
  ② prompt_length/mean            **恰好等于上限** = 全部被砍的指纹
  ③ 输入分布和训练时是不是同一个   契约五元组（06 §2.A 的 A3）
```

⚠️ 而且这不是第一次：`22 §P0-1.0` 记的是同一个形状——我用 `num_steps >= 8` 回溯分类截断原因，而真实上限是逐 case 4–14。**那次也是我自己犯的。**

⇒ 一般化：**回溯分类之前，先确认你用的那条阈值/那个输入，是不是这次真正生效的那个。**
