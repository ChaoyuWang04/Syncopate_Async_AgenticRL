**更新文档的默认动作是「就地改写」，不是「往后追加」。** 增量不禁止，但必须证明必要。

**Why：** 所有文档都默认增量更新 ⇒ 膨胀式生长（主线 00 曾 916 行、20 曾 1269 行、
19 份共 8334 行；infra meta 层曾 2600 行）⇒ 同一天两条线各来一道压缩令。
膨胀的文档不会有人来整理，只会被推倒重写 ——「先写完回头再整理」不成立。

**How to apply（动笔前四问）：**
1. 已有哪一节在讲同一件事？→ **合并进去**，不开新节
2. 本次更新推翻了哪些旧行？→ **同一次编辑里删掉或改掉**（不许新旧并存）
3. 这份文档的单一用途还成立吗？→ 不成立就拆/搬，不硬塞
4. 真的需要新开文档吗？→ 先问能不能进现有的某一份

- 允许追加的只有**登记型**内容：E 报告新实验小节 · 队列新任务行（办完删行）·
  决策/作废登记新行（理由变了就地改原行）
- 状态/结论/数字一律就地改；被取代的叙述就地删，历史去 git log
- 收尾看行数：比上次长而没有新结论 = 在堆历史，回去合并
